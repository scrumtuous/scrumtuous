01 / A fresh layer

Five boxes, one short recap

The full stack is already here. Angular replaces the hand-wired browser UI, while your existing authentication service, mission service, and Postgres keep their jobs. Spend about 10 minutes here, then give the rest of your attention to Angular.

Browser session

The trader sees the page. Angular runs inside this browser, not on a separate backend. The frontend owns pending, success and failure feedback.

Angular app

Components render UI; services coordinate requests. The later authentication lesson holds the access token in memory. A refresh loses that state unless a deliberate session strategy restores it.

Auth service • :3000

Receives the login JSON and issues tokens after checking credentials. Angular does not generate a valid JWT itself.

Mission service • :8081

Spring Boot validates protected requests and applies business rules. It accesses the database; the browser sends HTTP, not SQL.

Postgres

Persists the portfolio and order data. It does not receive the trader’s browser password from Angular.

  1. Angular sends username and password as JSON to the auth login endpoint.
  2. The successful response supplies an access token. Future protected requests attach Authorization: Bearer <token>.
  3. The mission service validates the token and the order, changes persisted data, then returns a response.
  4. The UI shows acceptance and refreshes or updates holdings to reflect the server’s result.

The supplied slide demo contrasts a protected order without a token (401) with an authenticated order that succeeds. This page does not run your backend or issue credentials.

02 / A fresh layer

Library or framework: who sets the shape?

A library supplies capabilities your application calls. A framework also defines a wider application structure and calls your code at the right moments. This is a spectrum of responsibility, not a ranking.

React: a UI library

React focuses on composing and rendering components. You describe UI from state, and React controls rendering and commit. It has its own rules, including hook rules, so “library” does not mean there is no inversion of control.

Core React leaves many application decisions open: routing, request conventions, validation and service organization. Browser fetch and native forms already work. Third-party packages are options, not mandatory for every operation.

Angular: an application framework

Angular coordinates components, templates, dependency injection, lifecycle and change detection. Its maintained ecosystem includes Router, HttpClient, forms, compiler and CLI, with common patterns for putting them together.

“Built in” means first-party integrated facilities. You still import and configure packages/providers. A router is not magically active in every component.

A React framework adds another layer around React. A team using one may already have established routing and data conventions. Compare Angular with the actual React stack you used, rather than assuming every React project is a blank slate.

// Plain browser library-style call
const response = await fetch("/api/holdings");

// Framework lifecycle: Angular creates the component,
// evaluates its template and invokes its handlers.
@Component({ selector: "app-status", standalone: true,
  template: `<button (click)="refresh()">Refresh</button>` })
export class StatusComponent { refresh(): void { /* application logic */ } }
The Angular excerpt illustrates framework control; it needs the Component import and a bootstrapped Angular application. Framework source examples below are reading material, while the labeled browser models run offline.

04 / A fresh layer

Read the same pancake counter twice

Angular • TypeScript

import { Component, computed, signal } from '@angular/core';
@Component({
  selector: 'app-pancake-counter',
  standalone: true,
  template: `
    <h2>Pancakes: {{ pancakes() }}</h2>
    <p>Syrup servings: {{ syrup() }}</p>
    <button (click)="reward()">Reward a slide ride</button>
    @if (pancakes() > 0) { <p>Breakfast is ready!</p> }
  `,
})
export class PancakeCounterComponent {
  readonly pancakes = signal(0);
  readonly syrup = computed(() => this.pancakes() * 2);
  reward(): void { this.pancakes.update(n => n + 1); }
}

React • TSX

import { useState } from 'react';
export function PancakeCounter() {
  const [pancakes, setPancakes] = useState(0);
  const syrup = pancakes * 2;
  function reward() { setPancakes(n => n + 1); }
  return (
    <>
      <h2>Pancakes: {pancakes}</h2>
      <p>Syrup servings: {syrup}</p>
      <button onClick={reward}>Reward a slide ride</button>
      {pancakes > 0 && <p>Breakfast is ready!</p>}
    </>
  );
}

Angular’s template is HTML with Angular bindings. The class keeps its fields and methods while Angular evaluates the template. React’s function returns an element description from the props and state of that render. JSX looks like HTML, but is JavaScript syntax transformed by tooling; braces enter JavaScript expressions.

  • (click)="reward()" is an Angular event binding. onClick={reward} passes a function to React. onClick={reward()} would call it while rendering.
  • Angular uses class and for in templates. React DOM JSX uses className and htmlFor.
  • [disabled]="busy()" binds an Angular DOM property. React uses disabled={busy}.
  • Angular can put HTML in templateUrl instead of an inline string. The binding language stays the same.

The React syrup calculation is cheap enough to calculate on each render. useMemo(() => expensiveCalculation(pancakes), [pancakes]) can cache expensive work, but is a performance tool, not the fundamental definition of derived state or a signal dependency graph.

Translate before looking

Translate Angular @if (busy()) { <p>Cooking</p> } into JSX. Then translate [disabled]="busy()".

Reveal solution and reasoning

Use {busy && <p>Cooking</p>} and disabled={busy}, assuming busy is a boolean state value. Remove the signal getter parentheses when using ordinary React state.

05 / A fresh layer

TypeScript, decorators and component metadata

An interface, import, exported class, private field, constructor and typed method are ordinary TypeScript concepts. Angular gives them a particular application role. @Component supplies Angular metadata; decorator syntax itself is broader than Angular, although decorator compatibility and compilation rules depend on the toolchain.

selector

app-pancake-counter identifies the component’s element selector. A parent can use that tag after importing the standalone component.

standalone

The component declares its own template dependencies through imports rather than being declared in an NgModule. Standalone does not mean isolated from services or routing.

template

The UI description. The compiler understands bindings and control flow and can report type errors when template checking is enabled.

interface Holding { ticker: string; quantity: number; }
// Holding is a compile-time shape, not a runtime validator.
const holdings = signal<Holding[]>([]);
// signal is Angular state machinery around an ordinary typed array.

readonly pancakes = signal(0);
// readonly protects the field reference; this is allowed:
this.pancakes.set(3);
// Replacing the wrapper is wrong and is caught by typing:
// this.pancakes = 3;
TypeScript types are erased at runtime. A server response can still be malformed. The server must validate requests, and a frontend may validate responses at its boundary. A generic such as HttpClient.get<Holding[]> describes an expected shape; it does not inspect the JSON.
06 / A fresh layer

A signal is a value with a reactive address

Keep the wrapper; change the value inside it. Calling pancakes() reads the current value. pancakes.set(5) replaces the value. pancakes.update(n => n + 1) computes the next value from the previous one.

import { signal, computed } from '@angular/core';
const pancakes = signal(0);
const syrup = computed(() => pancakes() * 2);
pancakes.set(3);
console.log(pancakes()); // 3: the getter reads the new value
console.log(syrup());    // 6
pancakes.update(n => n + 1);
console.log(syrup());    // 8

The call notation matters. Inside a computed derivation, effect, or template evaluation, Angular knows which consumer is executing. Reading the signal records a dependency. A plain console.log outside a reactive context reads a value but does not create a subscription that will log future values.

When a value changes, relevant consumers are invalidated or scheduled for an update. Angular integrates this with change detection. A signal read in an OnPush template marks that component when it changes. Do not interpret this as a promise that exactly one DOM node is checked or that other rendering work cannot occur.

07 / A fresh layer
Computed: derive it once, invalidate it when needed
Store source facts as writable signals. Derive totals, filters and labels with computed. A computed is read-only, lazy and cached: its calculation waits for the first read, repeated reads reuse the result, and a dependency change makes the cache stale. The next read calculates again.
With computed(() => pancakes() * 2), changing pancakes need not immediately perform the multiplication. Invalidating a cache and running a derivation are distinct events. You cannot call set on a computed; change the source facts instead.

readonly totalQuantity = computed(() =>
  this.holdings().reduce((sum, h) => sum + h.quantity, 0)

08 / A fresh layer
Dependencies follow the branch you actually read
Dependency tracking is dynamic. If a derivation does not read a signal on its current branch, that signal is not a dependency of that calculation. When the branch changes and the derivation runs again, the dependency set changes too.

Offline teaching model in plain JavaScript. Angular and React are not loaded.
Console output
  1. While closed, Add then Read: the cached “Booth closed” remains valid.
  2. Toggle open then Read: both open and pancakes are now dependencies.
  3. Add then Read: a new calculation gives the new reward count.
  4. Close and Read: pancakes is removed from the dependency set.
Tracking is synchronous. A signal first read after an await is outside the original reactive context. Read required dependencies before the await. For an incidental read that should not trigger an effect, Angular offers untracked; use it deliberately, not to conceal dependencies.
09 / A fresh layer
The array mutation trap
QUIZ ALERTThe supplied Sprint 9 assessment asks about an in-place array update leaving a computed total stale. It also asks why a separately maintained writable total can drift from its source rows.
Signals use Object.is equality by default. Arrays and objects are compared by reference. Pushing into an existing array changes its contents but does not send a new reference through the signal. A previously cached computed can remain stale, even though a direct read sees the mutated array.
// Wrong: mutation does not notify the signal graph.
holdings().push({ ticker: "MAPL", quantity: 2 });
// Also wrong: returning the same mutated reference.
holdings.update(rows => { rows.push(newHolding); return rows; });

// Correct: return a new array.
holdings.update(rows => [...rows, newHolding]);
// Correct: replace an edited row too.
holdings.update(rows => rows.map(h =>
  h.ticker === "MAPL" ? { ...h, quantity: h.quantity + 1 } : h
));

The initial show cached the total at two. Push changed the array in place without notifying that computed. Good creates a new array reference, invalidates it, and its next read includes all three rows for a total of four.
asReadonly prevents set/update through the exposed signal API; it does not deep-freeze the object or array inside. Custom equality is available but is an advanced design choice. Immutable updates are the clear default, and the same reference discipline is useful with React state.
10 / A fresh layer
Effects, inputs and shared state
Use computed for a value derived from other values. Use an effect when state must synchronize with a non-reactive API, such as logging or an external chart. Effects run initially and later when their tracked inputs change; their scheduling depends on the effect context and Angular version. Do not promise immediate execution after every set.
import { Component, effect, signal } from '@angular/core';
@Component({ selector: 'app-ride-log', standalone: true,
  template: `<button (click)="rides.update(addOne)">Ride</button>` })
export class RideLogComponent {
  readonly rides = signal(0);
  readonly addOne = (n: number) => n + 1;
  constructor() {
    effect((onCleanup) => {
      const n = this.rides();
      const timer = setTimeout(() => console.log('Rides:', n), 500);
      onCleanup(() => clearTimeout(timer));
    });
  }
}
This effect is created in a constructor injection context. Cleanup cancels the prior delayed log before a rerun or destruction, preventing obsolete work. Prefer a pure computed over an effect that copies one signal into another. Do not assume Angular effect and React useEffect have identical timing or dependency semantics.
import { Component, input } from '@angular/core';
@Component({ selector: 'app-reward-label', standalone: true,
  template: `<h2>{{ guest() }} earned pancakes</h2>` })
export class RewardLabelComponent {
  readonly guest = input.required<string>();
}
// Parent imports RewardLabelComponent and uses:
// <app-reward-label [guest]="guestName" />
An input signal receives a parent binding. This required input must be provided by the parent; the child reads it with guest() and cannot set it like its own writable state. Signal inputs are a component boundary, not a reason to duplicate parent state.
import { Injectable, signal, inject, Component } from '@angular/core';
@Injectable({ providedIn: 'root' })
export class Rewards {
  private readonly _pancakes = signal(0);
  readonly pancakes = this._pancakes.asReadonly();
  reward(): void { this._pancakes.update(n => n + 1); }
}
@Component({ selector: 'app-reward-board', standalone: true,
  template: `<p>{{ rewards.pancakes() }}</p>
    <button (click)="rewards.reward()">Reward</button>` })
export class RewardBoardComponent {
  readonly rewards = inject(Rewards);
}
inject asks Angular’s injector for an instance; it does not call a constructor chosen by the component. A root provider normally shares one instance per application injector. Adding a component-level provider can create a separate instance for that subtree. This is why provider scope matters for a shared reward count.
Signals hold a current value. RxJS observables represent streams over time with operators and subscription lifecycle. Angular’s HttpClient commonly returns an Observable; signals do not replace every stream or make HTTP synchronous. Later lessons connect request results to signal state and handle cancellation and errors.
11 / A fresh layer
React renders a snapshot; a signal getter reads now
A hook does not independently “rerun the whole function.” A state update tells React to render. During that render, React calls the component function again and the hooks provide the state for that render. React then commits necessary DOM changes; calling the function is not the same as rebuilding all DOM nodes.
Angular • TypeScript
rewardTwice(): void {
  this.pancakes.update(n => n + 1);
  this.pancakes.update(n => n + 1);
  console.log(this.pancakes()); // current updated value
}
React • TSX
function rewardTwice() {
  setPancakes(n => n + 1);
  setPancakes(n => n + 1);
  console.log(pancakes); // value from this render
}
// Functional updates compose in the queued next state.
React event handlers close over a render’s values. Two calls to setPancakes(pancakes + 1) in the same handler commonly request the same next value, adding one rather than two. Functional setters compose updates. Angular’s getter reads its current signal value synchronously, although rendering still has its own timing.
React can render because a parent renders or context changes, as well as its own state. Memoization and compiler optimizations can skip work. Hooks must follow their rules, including consistent top-level call order; Angular class field signals do not use that positional hook model.

Routing, HTTP, forms and DI: translate the job
These are familiar jobs with different APIs. Angular bundles first-party conventions; React teams choose browser APIs, libraries or framework facilities. Here are reading excerpts, not complete applications.
Angular • TypeScript
// Angular Router, configured by the app:
private readonly router = inject(Router);
openOrders(): void { this.router.navigate(['/orders']); }

// Angular HttpClient, with provideHttpClient() configured:
private readonly http = inject(HttpClient);
load(): void {
  this.http.get<Holding[]>('/api/holdings').subscribe({
    next: rows => this.holdings.set(rows),
    error: () => this.error.set('Could not load holdings'),
  });
}
React • TSX
// React core has no universal router hook.
// Your selected router/framework defines navigation.

// Browser fetch works from a React handler too:
async function load() {
  try {
    const response = await fetch('/api/holdings');
    if (!response.ok) throw new Error('HTTP failure');
    const rows = await response.json();
    setHoldings(rows);
  } catch { setError('Could not load holdings'); }
}
Router and HttpClient imports are from @angular/router and @angular/common/http; inject is from core. The excerpts assume the relevant fields and app providers exist. Repeated loads need a deliberate subscription/cancellation strategy, covered later. HttpClient handles JSON conversion, but error feedback is still your application’s job.
Angular • TypeScript
// Reactive forms: import from @angular/forms
readonly username = new FormControl('', { nonNullable: true,
  validators: [Validators.required, Validators.minLength(3)] });
// Standalone component imports ReactiveFormsModule
// Template: <input [formControl]="username">
React • TSX
const [username, setUsername] = useState('');
const invalid = username.length < 3;
// JSX:
<input value={username}
  onChange={e => setUsername(e.target.value)}
  aria-invalid={invalid} />
Angular offers template-driven and reactive forms; this course uses reactive forms later. React controlled inputs can be implemented directly with state; a form library helps when a team needs shared validation conventions or complex field management. Both still need accessible feedback and server validation.
Angular DI resolves providers in a hierarchy. React context distributes a value through a component tree; custom hooks can expose shared logic. Context is not the same provider/token construction system as Angular’s injector. Neither automatically makes arbitrary state globally shared.

import { Component, effect, inject, signal } from '@angular/core';
import { Router } from '@angular/router';
interface Holding { ticker: string; quantity: number; }
@Component({
  selector: 'app-holdings-list',
  standalone: true,
  template: `
    <h2>Holdings</h2>
    @for (holding of holdings(); track holding.ticker) {
      <p>{{ holding.ticker }}: {{ holding.quantity }}</p>
    } @empty { <p>No holdings yet.</p> }
    <button (click)="goToOrders()">Orders</button>
  `,
})
export class HoldingsListComponent {
  private readonly router = inject(Router);
  readonly holdings = signal<Holding[]>([]);
  constructor() {
    effect(() => console.log('Holding rows:', this.holdings().length));
  }
  goToOrders(): void { void this.router.navigate(['/orders']); }
}
Classify each meaningful line as familiar TypeScript/browser concept or Angular-specific machinery. Explain selector, standalone, template, inject, effect and track. Identify the statement that changes holdings.
Model annotations and reasoning
  • Imports, interface Holding, exported class, fields, constructor and typed method are familiar TypeScript. Interfaces describe data; they do not store it.
  • @Component metadata, signal, effect, inject(Router), interpolation and @for are Angular APIs/syntax. The event-handling concept is familiar even when its spelling is new.
  • inject(Router) resolves the configured router. new Router() would bypass the app’s dependency configuration and requires its dependencies.
  • effect observes the holdings read during its callback. It logs initially on its scheduled execution and can run again when holdings changes.
  • track holding.ticker preserves row identity across updates. This assumes tickers are unique and stable. Duplicate tickers need another stable key. React’s map list needs keys for the same identity problem.
  • holdings() reads the array. This example has no set/update, so it never changes the holdings signal. Calling the getter is not reassignment.
Angular • TypeScript
@for (holding of holdings(); track holding.ticker) {
  <p>{{ holding.ticker }}: {{ holding.quantity }}</p>
}
React • TSX
{holdings.map(holding => (
  <p key={holding.ticker}>
    {holding.ticker}: {holding.quantity}
  </p>
))}

addHolding(): void {
  this.holdings.update(rows => rows.some(h => h.ticker === "MAPL")
