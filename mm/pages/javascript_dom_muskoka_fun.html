01 / A fresh layer

The cottage has a live document

HTML built the breakfast counter. CSS dressed it. Now JavaScript responds when Raccoon orders another stack or Beaver checks the packing list. The browser’s DOM is a live, in-memory document tree.

Browser JavaScript

Runs with document, window, rendered elements, and user events. It can update the page while you stay on it.

Node.js comparison

Ordinary Node.js does not provide a browser DOM or window. It does provide server-side APIs. The language is shared; the environment differs.

A DOM node is not always an element: text and comments can be nodes too. Changing the DOM changes what the browser renders, but does not rewrite your saved HTML file.

addEventListener registers a callback; it does not run the callback immediately. Use event names such as click, submit, and input, without an “on” prefix. JavaScript can toggle a class while CSS defines its appearance.

Find the silent new task
Remove wireTask(li), run again, add a task, and click it. Then restore the line. Why did the original tasks still work?
Reveal solution and reasoning
The initial query selected only nodes that existed at that moment. It attached listeners to those nodes. The new node did not inherit them. Another solution is event delegation: attach one listener to the list, then examine event.target. For production accessibility, use a button or checkbox inside each task so keyboard users can perform the same action.

04 / A fresh layer
Keep the page at the cottage
Submitting an ordinary form performs its default submission/navigation. Your single-page handler should call event.preventDefault() synchronously, before branching or awaiting asynchronous work. It cancels the default action; it does not stop event propagation.
QUIZ ALERTSprint 9 asks why preventDefault belongs before the validation branch. If it runs only when invalid, a valid submission still follows the browser’s default navigation. Cancel the default for every submission handled by your JavaScript.

Feedback without stale red borders
Read values first. Compute plain booleans. Then update the DOM. Mark both inputs on every submit: a field that was invalid yesterday needs its red border removed when it becomes valid.
const usernameOk = username.length >= 3;

Make the welcome message syrup-safe
Enter <strong>maple</strong> as the username in the playground. Should it become bold markup inside the welcome message?
Reveal solution and reasoning
No. textContent displays user text as text. Assigning untrusted input through innerHTML can interpret markup and introduce injection problems. There is no reason to parse markup in this welcome message.
QUIZ ALERTNative constraints and JavaScript validation improve the interaction. Both are client-side and can be bypassed. Later quiz questions require independent server-side validation too.
06 / A fresh layer
Window: the cottage’s surroundings
window represents the browser browsing context. document is its current document. Browser globals include console and setTimeout. Top-level let and const bindings do not become window properties; top-level var in a classic script usually does. Module bindings stay in the module.

setTimeout schedules a callback after at least the requested delay; it does not pause JavaScript or guarantee an exact time. Node.js also has built-in timers, so using setTimeout there does not require a package.
DOMContentLoaded means the document has been parsed, with deferred/module scripts executed. The window load event waits for dependent resources such as images as well. Browser access to files is permission-based, not unrestricted like ordinary server filesystem access.
Optional cottage preference: localStorage
try {
  localStorage.setItem("cottage-chair", "red");
  console.log(localStorage.getItem("cottage-chair"));
  localStorage.removeItem("cottage-chair");
} catch (error) {
  console.log("Storage is unavailable in this context.");
}
Storage belongs to an origin and commonly persists between page loads. File URL behavior is not portable, and this sandbox intentionally lacks same-origin access, so storage may be blocked. Try this optional snippet in your own HTTP-served page. Do not store passwords. Reveal full Lab 03 JavaScript solution
const form = document.getElementById("login-form");
const usernameInput = document.querySelector("#username");
const passwordInput = document.querySelector("#password");
const message = document.getElementById("message");
function markInvalid(input, invalid) {
  input.classList.toggle("invalid", invalid);
  input.setAttribute("aria-invalid", String(invalid));
}
function showMessage(text, kind) {
  message.textContent = text;
  message.className = kind;
}
form.addEventListener("submit", (event) => {
  event.preventDefault(); // every path stays on this page
  const username = usernameInput.value;
  const password = passwordInput.value;
  const usernameOk = username.length >= 3;
  const passwordOk = password.length >= 8;
  markInvalid(usernameInput, !usernameOk);
  markInvalid(passwordInput, !passwordOk);
  if (!usernameOk || !passwordOk) {
    showMessage("Username needs 3+ characters, password needs 8+.", "error");
    return;
  }
  showMessage(`Welcome, ${username}. (No real request sent yet.)`, "success");
  form.reset();
});
usernameInput.addEventListener("input", () => {
  if (usernameInput.value.length >= 3) markInvalid(usernameInput, false);
});
