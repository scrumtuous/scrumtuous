01 / A fresh layer

Je me souviens: one shared source of truth

Raccoon and Beaver both need the portfolio total, just as both need the same cheese platter. Copying the platter’s inventory into two notebooks creates two truths. Move the holdings into a service, and let every interested component read that same source.

In Module 08, HoldingsSummary owned a local signal and computed total. That is fine for local state. A separate header badge cannot cleanly read the component’s private implementation. Copying its seed data into the badge does not share anything; later additions affect only one copy.

Before

Summary owns rows. Badge owns another set of rows. Two independent totals can disagree.

After

Holdings service owns rows and mutation methods. Summary and badge receive the same service instance and read its signals.

Lab 09 is a refactor first: keep the existing add/remove behavior and numbers. Then add the badge to demonstrate the new sharing capability. No backend or HTTP request is introduced here.

02 / A fresh layer

A service is a class; DI supplies the dependency

A service organizes state or reusable behavior outside a particular view. Dependency injection means the consumer asks for a dependency supplied by a configured injector instead of constructing and choosing it internally.

npx ng generate service holdings
# Later, generate the second view:
npx ng generate component portfolio-badge --standalone
import { Injectable } from '@angular/core';
@Injectable({ providedIn: 'root' })
export class Holdings {}

For this Angular 21 course, use @Injectable, the CLI’s supported generated pattern. Newer documentation may show @Service shorthand; do not swap in a newer API without checking your installed version.

@Injectable supplies Angular metadata for resolving the class’s dependencies. providedIn: 'root' registers its provider in the application root injector. An injectable class still needs a provider registration to be resolved; the decorator and registration are related but distinct jobs. A simple class can also be explicitly provided with a configured value or factory.

Angular can create the root service when it is first requested and reuse it for later requests in that scope. This is one instance per application root injector when no closer provider overrides it, not one instance for every user, browser tab or server in existence.

// These create separate objects and bypass the injector cache:
const first = new Holdings();
const second = new Holdings();
console.log(first === second); // false
// In Angular-created consumers, request it instead:
private readonly holdingsService = inject(Holdings);
03 / A fresh layer

Move the state and mutation policy together

Move the Holding interface, seeded signal, computed total and add/remove operations into holdings.ts. The interface is exported so other files can refer to the data shape. Holdings is a class and runtime injection token; Holding is only a TypeScript interface.

import { Injectable, computed, signal } from '@angular/core';

export interface Holding {
  ticker: string;
  quantity: number;
  price: number;
}

@Injectable({ providedIn: 'root' })
export class Holdings {
  private readonly holdings = signal<Holding[]>([
    { ticker: 'ULVR.L', quantity: 500, price: 42.1 },
    { ticker: 'AZN.L', quantity: 120, price: 108.5 },
  ]);

  readonly all = this.holdings.asReadonly();
  readonly totalValue = computed(() =>
    this.holdings().reduce((sum, h) => sum + h.quantity * h.price, 0),
  );
  readonly hasBP = computed(() =>
    this.holdings().some(h => h.ticker === 'BP.L'),
  );

  add(holding: Holding): void {
    // This lesson has one row per ticker: preserve unique track keys.
    this.holdings.update(current =>
      current.some(h => h.ticker === holding.ticker)
        ? current
        : [...current, { ...holding }]);
  }

  remove(ticker: string): void {
    this.holdings.update(current =>
      current.filter(h => h.ticker !== ticker));
  }
}

The private signal is the writable source. all is a read-only signal view of that source, not a new snapshot. Calling all() later returns the current array. totalValue remains a computed over the private signal, so its dependency invalidation still follows the immutable update rules from Module 08.

The service methods define the allowed ways to change this portfolio. add creates a new array and a shallow copy of the supplied row. remove filters into a new array. A caller can request a change without gaining the source signal’s set/update API.

This companion solution preserves the previous page’s one-row-per-ticker rule and duplicate BP.L guard. A duplicate add returns the existing array as an intentional no-op; no contents have been mutated. Returning the same reference is correct for an actual no-op, and wrong after changing its contents.

If your domain supports several lots of the same ticker, use a stable row id and update the service policy, remove method and @for track key together. The type interface alone does not enforce unique tickers.
04 / A fresh layer

Private, readonly and asReadonly protect different things

These three words are not interchangeable. Understand the boundary before assuming that exposed state is deeply immutable.

MechanismProtectionLimit
private holdingsOrdinary outside TypeScript code cannot reference the member.TypeScript private is checked at compile time; it is not an ECMAScript #private field or security boundary.
readonly all fieldThe class field cannot be reassigned through normal TypeScript code.It does not freeze the value returned by all().
asReadonly()Exposes a callable Signal with no set/update methods.It is a read-only signal API, not a deep-frozen array or object.
computed totalValueDerived read-only value with tracked source dependencies.Incorrect in-place mutation can still leave its cache stale.
// In a consumer, both attempts are wrong:
// service.holdings.set([]); // private member: type error
// service.all.set([]);      // read-only Signal has no set

// This can still mutate a mutable payload, so avoid it:
// service.all().push(newHolding);
// Use the intended command:
service.add(newHolding);

Making the internal source public would allow callers to bypass your add/remove policy. Leaving it private and exposing all removes direct signal writes from the consumer API. It does not prevent a caller from modifying a mutable array received from the getter.

For stronger compile-time discipline, expose readonly array and row types where appropriate. readonly array types block push through that typed reference; readonly row properties discourage nested assignment. Runtime freezing is a separate choice and shallow freezing does not recursively freeze everything. None of these replace proper signal updates.

05 / A fresh layer
Refactor the component without rewriting its template
Keep the names that the template already uses. The component’s holdings field now aliases the service’s all signal; totalValue aliases the service’s computed. These assignments keep references to callable signals, not copies of their current values.
import { Component, inject } from '@angular/core';
import { DecimalPipe } from '@angular/common';
import { Holdings } from '../holdings';

@Component({
  selector: 'app-holdings-summary',
  standalone: true,
  imports: [DecimalPipe],
  templateUrl: './holdings-summary.html',
  styleUrl: './holdings-summary.css',
})
export class HoldingsSummary {
  private readonly holdingsService = inject(Holdings);
  protected readonly holdings = this.holdingsService.all;
  protected readonly totalValue = this.holdingsService.totalValue;
  protected readonly hasBP = this.holdingsService.hasBP;

  protected addHolding(): void {
    this.holdingsService.add({ ticker: 'BP.L', quantity: 200, price: 4.8 });
  }
  protected removeHolding(ticker: string): void {
    this.holdingsService.remove(ticker);
  }
}
// Keep the getter, not a one-time snapshot:
protected readonly holdings = this.holdingsService.all;
// Avoid this refactor if you intend reactive reads:
// protected readonly holdings = this.holdingsService.all();
The service field must be initialized before the aliases that use it. Angular creates this component in an injection context, so the field initializer can call inject. The click method later calls the already-injected service; it does not ask the injector again.
hasBP is retained because our Module 08 template disables duplicate BP.L adds. If you followed the original slide’s simpler template, you do not need that binding, but still need a coherent unique-key policy. The HTML can remain unchanged for the version you already built.
The same holdings-summary.html from Module 08

The component still handles the UI event and displays data. The service performs the domain change. Summary does not select or message the badge, and the service does not manipulate either component’s DOM.
06 / A fresh layer
The badge reads the exact same computed
Generate PortfolioBadge, inject Holdings, and expose its totalValue to the badge’s template. DecimalPipe belongs in the badge’s own imports too; another component importing it does not make it globally available.
import { Component, inject } from '@angular/core';
import { DecimalPipe } from '@angular/common';
import { Holdings } from '../holdings';

@Component({
  selector: 'app-portfolio-badge',
  standalone: true,
  imports: [DecimalPipe],
  template: `<span>Portfolio: {{ totalValue() | number: '1.2-2' }}</span>`,
})
export class PortfolioBadge {
  private readonly holdingsService = inject(Holdings);
  protected readonly totalValue = this.holdingsService.totalValue;
}
  1. Angular creates HoldingsSummary and resolves its Holdings token.
  2. The root provider creates or returns the root instance.
  3. Angular creates PortfolioBadge and resolves the same token through the same root scope.
  4. No closer provider exists, so it returns that same object.
  5. A summary click calls add on that object, changing its source signal.
  6. The computed cache is invalidated. Angular refreshes dependent views through its signal integration; each template reads the new derived value.
The JavaScript getter can reflect a source update synchronously, while rendering follows Angular’s scheduling. “Both update together” describes the resulting consistent UI, not a guarantee that DOM changes occur in the same instruction as add().

07 / A fresh layer
Provider scope: the nearest registration matters
providedIn: 'root' supplies a default root registration. A closer registration of the same token can shadow it. Two callers share an instance when their resolution reaches the same provider instance, not merely because they import the same class.
// Root sharing: omit component providers for Holdings.
@Component({ /* template metadata */ })
export class HoldingsSummary { private service = inject(Holdings); }

// Intentional local instance: shadows the root for this component/subtree.
@Component({ providers: [Holdings], /* template metadata */ })
export class IsolatedSummary { private service = inject(Holdings); }
Provider placementResult
Root onlySibling summary and badge normally resolve the same application instance.
Summary component onlySummary and its descendants can use the local instance; a sibling badge still sees root state.
Both sibling components separatelyEach gets its own local provider instance; their changes do not automatically synchronize.
Their common parentBoth descendants can share the parent instance; outside that subtree can still use root state.

Select a scope and recreate the consumers. With Root, Add changes both. With Summary component, Add changes only the summary. With Common parent, both share the subtree instance. Recreating a scope resets the model state intentionally; ordinary change detection does not construct a new service on every pass.
Use a local scope when isolation is desired, for example two independent portfolio editors. Remove accidental local providers when you intend the header and list to share root state. Router environment providers can also create distinct scopes in larger apps; inspect registrations rather than assuming all services are global.
08 / A fresh layer
Know where inject works, and where it does not
inject requires an active injection context. Angular-created component/service field initializers and constructors are common valid places. An arbitrary later method or lifecycle hook is not automatically a context just because it belongs to an Angular class.
export class HoldingsSummary {
  private readonly service = inject(Holdings); // valid field initializer
  protected addHolding(): void {
    this.service.add({ ticker: 'BP.L', quantity: 200, price: 4.8 });
    // Avoid calling inject(Holdings) here in a click handler.
  }
}
Constructor injection is another supported style: constructor(private readonly service: Holdings) {}. Either way, the consumer receives its dependency; it does not construct the selected service. Keep the course’s field-inject style consistent while learning.
Optional: why an interface is not an injection token
// An interface disappears at runtime, so inject(Holding) is invalid.
// The class Holdings remains a runtime value and works as a token.
// For a configuration value, use an explicit token:
import { InjectionToken } from '@angular/core';
export const API_URL = new InjectionToken<string>('API_URL');
// Register { provide: API_URL, useValue: '/api' } in app providers,
// then inject(API_URL) in a valid context.
The token identifies a dependency. The provider chooses how to supply it. Providers can use a class, existing instance, value or factory. This lesson needs only the root class-provider pattern.
09 / A fresh layer
Component or service: choose by responsibility
Shared portfolio facts, mutation policy, authentication state and data access are good service responsibilities. Template layout, focus behavior, and whether this particular dropdown is open usually belong to a component.
ResponsibilityLikely homeReason
Portfolio rows and totalHoldings serviceMultiple views need one consistent source.
Add/remove policyHoldings serviceEvery caller follows the same rules.
Badge layout and number displayPortfolioBadge templatePresentation belongs to the view.
One dropdown’s open/closed stateThat componentIt may have no reason to outlive or be shared beyond the view.
A pure reusable calculationPlain function may sufficeNo state, lifecycle or DI configuration may be needed.
Future API fetch and error stateService, in Module 10Coordinate data access and shared results.
The slide’s “a second component might need it” is a useful prompt, not a demand to put every field in a root service. Decide the sharing boundary. A parent can own state for a small subtree, and a pure function can share logic without creating a stateful service.
Root state normally survives the destruction of one consumer, but it is still browser memory. Refreshing the app resets seeded state. Other tabs and other users have independent app instances. Persistence, backend synchronization and real authorization remain separate responsibilities.

Lab questions: model reasoning
Why do the siblings share? Their token lookups resolve to the same root provider’s cached object, with no local overrides. What must a third component do? Inject the same service and call its methods; no new synchronization bridge is needed.
What if the source becomes public? Normal TypeScript can then access its writable set/update API and bypass the intended commands. all remains a read-only API, but mutable contents still require discipline. TypeScript private is not a browser-security defense.
