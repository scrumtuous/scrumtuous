01 / A fresh layer

One HTTP journey: mock API to Spring Boot

HttpClient is the frontend’s HTTP abstraction. The backend can be a tiny Node mock or a Spring Boot service: the browser still sends a request to a URL and receives an HTTP response. Combine the two modules by learning the request machinery once, then changing the service on the other end.

A dependency-free mock server on 3500 returns holdings or a deliberate 500. Practice loading, errors and preserving existing data.

Lab 11 • real harbor

02 / A fresh layer

Configure HttpClient in the application

Keep the explicit provider configuration from the course. Add provideHttpClient to app.config.ts while preserving the router and existing providers. Do not put HttpClient in a component’s template imports array.

import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';
export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes),
    provideHttpClient(),
  ],
};
import { HttpClient } from '@angular/common/http';
import { inject } from '@angular/core';
private readonly http = inject(HttpClient);

HttpClient is resolved through DI. Its methods return Observables. The response body is parsed as JSON by default. Your generic Holding[] gives TypeScript an expected response type, but does not validate actual JSON at runtime. An unexpected object shape can still reach your code.

Current documentation describes additional built-in defaults and backend options. Explicit provideHttpClient() remains the course’s clear configuration point and the place later interceptor features are added. Use the project’s installed Angular version rather than copying newer APIs blindly.

03 / A fresh layer

Fetch starts now; an HTTP Observable starts on subscription

A Promise represents the eventual result of work. fetch starts its request when called, whether or not you await it. A normal HttpClient request Observable is cold: creating it describes work; subscribing starts that work. That distinction explains a method that runs yet produces no Network entry.

ConcernfetchHttpClient
StartCalling fetch dispatches the request.Subscribing dispatches the described request.
JSONawait response.json() explicitly.Parsed JSON body is the default emission.

Type argumentNo built-in runtime schema checking.get<Holding[]> is a type assertion, not validation.

// No subscription yet, so no HTTP request yet.
request$.subscribe(rows => console.log(rows)); // request 1
request$.subscribe(rows => console.log(rows)); // request 2

04 / A fresh layer
Read next, error and complete as separate outcomes
A subscription has channels for emitted values, a terminal error, and normal completion. In the usual response-body mode, an HTTP request emits the parsed body and completes. Error terminates that request stream unless an operator supplies replacement behavior.
this.http.get<Holding[]>(url).subscribe({
  next: rows => this.holdings.set(rows),
  error: error => this.loadError.set(error.message),
  complete: () => console.log("Request stream complete"),
});
pipe composes operators around that Observable. catchError handles an upstream error and switches to the replacement it returns. Here, of(null) emits null once and completes. It does not retry, preserve the original failed HTTP request, or keep an infinite stream running.
this.http.get<Holding[]>(url).pipe(
  catchError(error => {
    this.loadError.set(errorMessage(error));
    return of(null);
  }),
).subscribe(data => {
  if (data !== null) this.holdings.set(data);
});
catchError needs a replacement ObservableInput; of(null) is the simple Observable used in this course. Returning plain null is not equivalent. A separate subscribe error handler is also valid; the operator pattern becomes especially useful when composing dependent requests.
05 / A fresh layer
Failure is not a successful empty portfolio
A successful [] means there are no holdings. A failed request means we could not learn the current holdings. Keep those meanings separate so a lighthouse outage does not erase the trader’s portfolio on screen.
ResultSet source rows?UI meaning
200 with a populated arrayYes, replace previous rows.New data loaded.
200 with []Yes, replace with empty array.Confirmed empty portfolio.
500 recovered as nullNo, retain previous rows.Load failed; existing display may be stale.
Network failure recovered as nullNo, retain previous rows.Could not reach/read the service; offer an appropriate retry.
JavaScript empty arrays are truthy, so the original if(data) accepts a successful []. This lesson uses data !== null to state the sentinel policy explicitly. Returning of([]) from catchError is allowed by RxJS, but unconditionally setting that result would turn failure into an empty list and overwrite good data.

// Companion mock API, plain Node.js. Start outside src: node mock-server.cjs
const http = require('node:http');
const rows = [
  { ticker: 'VOD.L', quantity: 800, price: 0.72 },
  { ticker: 'HSBA.L', quantity: 300, price: 6.4 },
];
const ALLOWED_ORIGIN = 'http://localhost:4200';
const server = http.createServer((req, res) => {
  if (req.headers.origin === ALLOWED_ORIGIN) {
    res.setHeader('Access-Control-Allow-Origin', ALLOWED_ORIGIN);
    res.setHeader('Vary', 'Origin');
  }
  res.setHeader('Access-Control-Allow-Methods', 'GET, OPTIONS');
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type');
  if (req.method === 'OPTIONS') { res.writeHead(204); res.end(); return; }
  res.setHeader('Content-Type', 'application/json');
  if (req.method === 'GET' && req.url === '/api/holdings') {
    res.writeHead(200); res.end(JSON.stringify(rows));
  } else if (req.method === 'GET' && req.url === '/api/holdings/error') {
    res.writeHead(500); res.end(JSON.stringify({ message: 'The lighthouse API is temporarily unavailable' }));
  } else { res.writeHead(404); res.end(JSON.stringify({ message: 'Not found' })); }
});
if (require.main === module) server.listen(3500, () => console.log('Mock API on http://localhost:3500'));

Complete upgraded holdings.ts service
import { Injectable, computed, inject, signal } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { catchError, finalize, of } from 'rxjs';
import { errorMessage } from './error-message';

export interface Holding {
  ticker: string;
  quantity: number;
  price: number;
}

@Injectable({ providedIn: 'root' })
export class Holdings {
  private readonly http = inject(HttpClient);
  readonly loadError = signal<string | null>(null);
  readonly loading = signal(false);
  private readonly holdings = signal<Holding[]>([
    { ticker: 'ULVR.L', quantity: 500, price: 42.1 },
    { ticker: 'AZN.L', quantity: 120, price: 108.5 },
  ]);

  readonly all = this.holdings.asReadonly();
  readonly totalValue = computed(() =>
    this.holdings().reduce((sum, h) => sum + h.quantity * h.price, 0),
  );
  readonly hasBP = computed(() =>
    this.holdings().some(h => h.ticker === 'BP.L'),
  );

  add(holding: Holding): void {
    // This lesson has one row per ticker: preserve unique track keys.
    this.holdings.update(current =>
      current.some(h => h.ticker === holding.ticker)
        ? current
        : [...current, { ...holding }]);
  }

  remove(ticker: string): void {
    this.holdings.update(current =>
      current.filter(h => h.ticker !== ticker));
  }

  loadFromApi(url: string): void {
    if (this.loading()) return; // prevent overlapping loads in this exercise
    this.loading.set(true);
    this.loadError.set(null);
    this.http.get<Holding[]>(url).pipe(
      catchError((error: unknown) => {
        this.loadError.set(errorMessage(error));
        return of(null); // failure sentinel, NOT an empty successful portfolio
      }),
      finalize(() => this.loading.set(false)),
    ).subscribe(data => {
      if (data !== null) {
        this.loadError.set(null);
        this.holdings.set(data);
      }
    });
  }
}
The full service preserves private rows, all, totalValue, hasBP and immutable commands from Lab 09. It adds HttpClient, loading and loadError. The load guard prevents overlapping requests in this exercise; finalize clears loading after success, handled error or unsubscription.

07 / A fresh layer
Bring the server’s message through the error boundary
HttpErrorResponse.message often describes the HTTP failure in general. error.error can contain the server’s parsed JSON response body. That body’s message may explain the business rule, such as a SELL exceeding the current holding.
import { HttpErrorResponse } from '@angular/common/http';
export function errorMessage(error: unknown): string {
  if (error instanceof HttpErrorResponse) {
    const body = error.error as { message?: unknown } | null;
    if (typeof body?.message === 'string') return body.message;
    if (error.status === 0) return 'Could not reach the service. Check the server, network and CORS.';
    return error.message;
  }
  return error instanceof Error ? error.message : 'Unexpected request failure';
}
The instanceof check handles the HTTP case. Optional chaining safely handles an absent body; the typeof check ensures the chosen message is a string. A status 0 can come from a transport or browser-access failure, including CORS. It is not proof that the server specifically rejected authentication.
A 400 or another application validation status can carry a useful business message. A 401 commonly means credentials/token were not accepted; a 403 commonly means permission was denied. Do not expose backend stack traces as user feedback. Preserve a useful message and use logs/Network for diagnosis.
QUIZ ALERTA related quiz asks why error.error?.message is more informative than error.message alone, and why optional chaining avoids a second failure when the body is absent.

08 / A fresh layer
CORS belongs on each API server
The browser origin includes scheme, host and port. Angular 4200, auth 3000 and mission 8090 are different origins. Each contacted API must allow the page’s origin. A successful curl request does not prove browser CORS works, because curl does not enforce the browser’s read-access policy.
// Auth service main.ts, using the supplied Nest setup:
app.enableCors({ origin: "http://localhost:4200" });
// Mission service SecurityConfig.java: integrate with its existing rules.
http.cors(cors -> cors.configurationSource(corsConfigurationSource()));

@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("http://localhost:4200"));
    config.setAllowedMethods(List.of("GET", "POST", "OPTIONS"));
    config.setAllowedHeaders(List.of("Content-Type", "Authorization"));
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}
Imports for the CORS types come from org.springframework.web.cors; Bean and List use their usual Spring/Java imports. Preserve the existing token-validation and authorization rules. Spring Security’s CORS integration lets preflight handling occur appropriately before authentication; do not disable API security to fix CORS.
A JSON POST or Authorization header can trigger an OPTIONS preflight. The server must permit the requested origin, method and headers. The bearer token belongs on the actual protected request; the preflight asks whether that request is allowed from the browser origin.

09 / A fresh layer
Chain login into the protected order with switchMap
The second request needs a value from the first. Login emits an access token; switchMap receives that value and returns the order request Observable. One subscription runs the composed operation.
import { Injectable, inject, signal } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { catchError, finalize, of, switchMap } from 'rxjs';
import { errorMessage } from './error-message';

export interface OrderRequest {
  ticker: string;
  instrumentType: 'EQUITY';
  quantity: number;
  price: number;
  side: 'BUY' | 'SELL';
}
// Subset of the course response. Match your server DTO before expanding it.
export interface OrderResponse {
  status: string;
  fee: number;
  newHoldingQuantity: number;
}
interface AuthResponse { accessToken: string; }
const AUTH_URL = 'http://localhost:3000/auth/login';
const MISSION_URL = 'http://localhost:8090/accounts/1/orders';

@Injectable({ providedIn: 'root' })
export class MissionApi {
  private readonly http = inject(HttpClient);
  readonly lastOrder = signal<OrderResponse | null>(null);
  readonly error = signal<string | null>(null);
  readonly pending = signal(false);

  submitOrder(order: OrderRequest): void {
    if (this.pending()) return; // one in-flight write in this classroom example
    this.pending.set(true);
    this.error.set(null);
    this.lastOrder.set(null);
    this.http.post<AuthResponse>(AUTH_URL, {
      username: 'alice', password: 'mission123', // classroom stand-in only
    }).pipe(
      switchMap(auth => {
        if (typeof auth.accessToken !== 'string' || !auth.accessToken) {
          throw new Error('Login response did not contain an access token');
        }
        return this.http.post<OrderResponse>(MISSION_URL, order, {
          headers: { Authorization: `Bearer ${auth.accessToken}` },
        });
      }),
      catchError((error: unknown) => {
        this.error.set(errorMessage(error));
        return of(null);
      }),
      finalize(() => this.pending.set(false)),
    ).subscribe(response => {
      if (response !== null) this.lastOrder.set(response);
    });
  }
}
  1. Check pending, mark the submission active and clear earlier feedback.
  2. Create the login POST with classroom credentials.
  3. On subscription, send login. The outer Observable emits the auth response.
  4. switchMap receives auth and creates the protected POST using its accessToken.
  5. The returned inner Observable is subscribed by the operator, sending the order.
  6. A downstream catchError sees errors from either HTTP request.
  7. A non-null result becomes lastOrder. finalize clears pending.
A thrown missing-token error inside the projection also enters the chain’s error path. If login fails, the order request is never reached. Nested subscriptions are possible, but the outer subscription’s error handler does not automatically catch errors from an independently subscribed inner request.
switchMap replaces an active inner subscription when its outer source emits another value. Here login normally emits once, so it serves the dependency chain. Calling submitOrder twice would create two separate chains; switchMap inside one does not cancel the other. The pending guard and disabled button prevent that classroom double submission.
For repeated write events, do not assume cancellation means rollback. A server may already have accepted the order. A production policy may ignore extra clicks with exhaustMap or queue with concatMap, and needs a server-side duplicate/idempotency strategy. These are later design choices, not additions required for this lab.
QUIZ ALERTThe supplied switchMap quiz targets one composable chain, ordered dependency, and a catchError that can handle both stages. It does not claim the two requests run simultaneously or that nested subscriptions are forbidden.

The component shape stays familiar
PlaceOrder injects MissionApi, aliases its signals, and delegates one button to submitOrder. JsonPipe displays the response for this learning exercise, so you can compare it with the Network response body. Later UI can format selected fields.
import { Component, inject } from '@angular/core';
import { JsonPipe } from '@angular/common';
import { MissionApi } from '../mission-api';
@Component({
  selector: 'app-place-order',
  standalone: true,
  imports: [JsonPipe],
  template: `
    <button type="button" [disabled]="pending()" (click)="submitTestOrder()">
      {{ pending() ? 'Submitting...' : 'Submit test BUY order' }}
    </button>
    @if (error()) { <p role="alert">{{ error() }}</p> }
    @if (lastOrder(); as response) {
      <h3>Latest response</h3><pre>{{ response | json }}</pre>
    }
  `,
})
export class PlaceOrder {
  private readonly missionApi = inject(MissionApi);
  protected readonly lastOrder = this.missionApi.lastOrder;
  protected readonly error = this.missionApi.error;
  protected readonly pending = this.missionApi.pending;
  protected submitTestOrder(): void {
    this.missionApi.submitOrder({
      ticker: 'ULVR.L', instrumentType: 'EQUITY',
      quantity: 1, price: 40, side: 'BUY',
    });
  }
}
