From a hardcoded order to a real form

Summer in New England: Raccoon picks the ticker, Beaver counts the quantity, and Narwhal waits for the pancake reward. Replace the single hardcoded order button with a form whose model lives in your Angular component.

02 / A fresh layer

What reactive actually means

A FormControl represents one field: value, validity, errors and interaction state. A FormGroup gives named controls one parent model. FormBuilder is a factory that reduces the setup code. ReactiveFormsModule supplies directives that connect that model to DOM inputs.

Editing a field updates the control through a value accessor; Angular runs validators and updates the group state. The model also exposes valueChanges and statusChanges Observable streams. This is the classic @angular/forms reactive-forms API. A FormControl is not a writable signal, and a FormGroup is not a computed signal. Newer Signal Forms are a separate API and outside this PDF.

const name = new FormControl('Raccoon', { nonNullable: true });
name.setValue('Beaver');
console.log(name.value); // Beaver
// UI input <input [formControl]="name"> reflects the model.

Template-driven forms use directives such as ngModel to establish the model from template bindings. Reactive forms explicitly establish the model in TypeScript, making complex state and programmatic changes easier to inspect. Keep the lesson’s reactive bindings together; do not mix ngModel into these controls.

03 / A fresh layer

Build the order model and understand each validator

import { Component, inject } from '@angular/core';
import { JsonPipe } from '@angular/common';
import { FormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { MissionApi } from '../mission-api';

@Component({
  selector: 'app-place-order',
  standalone: true,
  imports: [ReactiveFormsModule, JsonPipe],
  templateUrl: './place-order.html',
  styleUrl: './place-order.css',
})
export class PlaceOrder {
  private readonly fb = inject(FormBuilder);
  private readonly api = inject(MissionApi);
  protected readonly pending = this.api.pending;
  protected readonly error = this.api.error;
  protected readonly lastOrder = this.api.lastOrder;

  // Number inputs can become null when cleared, even with a default value.
  protected readonly orderForm = this.fb.group({
    ticker: this.fb.nonNullable.control('ULVR.L', Validators.required),
    instrumentType: this.fb.nonNullable.control<'EQUITY' | 'BOND'>('EQUITY', Validators.required),
    quantity: this.fb.control<number | null>(1, [Validators.required, Validators.min(0.01)]),
    price: this.fb.control<number | null>(40, [Validators.required, Validators.min(0.01)]),
    side: this.fb.nonNullable.control<'BUY' | 'SELL'>('BUY', Validators.required),
  });

  protected submit(): void {
    if (this.pending()) return;
    // valid also rejects PENDING or DISABLED forms; invalid alone does not.
    if (!this.orderForm.valid) {
      this.orderForm.markAllAsTouched();
      return;
    }
    const value = this.orderForm.getRawValue();
    // Angular validation is runtime state, not a TypeScript narrowing operation.
    if (value.quantity === null || value.price === null) return;
    this.api.submitOrder({ ...value, quantity: value.quantity, price: value.price });
  }

  protected reset(): void {
    if (this.pending()) return;
    this.orderForm.reset({ ticker: 'ULVR.L', instrumentType: 'EQUITY', quantity: 1, price: 40, side: 'BUY' });
  }
}

inject(FormBuilder) obtains the form factory. The group keys mirror the order DTO. Each control receives its initial value and validators. required rejects empty values, but whitespace-only strings still pass it. A custom trimmed-text validator or normalization may be useful later. min(0.01) rejects numbers below 0.01; it does not make a blank field required, so use both validators.

The PDF says “greater than 0,” but its actual rule is at least 0.01: 0.005 is positive and still invalid. These are different boundaries. Client and server positivity checks overlap; the server must still enforce its own rule. Checking SELL against the current holding is a separate state-dependent business rule.

Text/select controls use nonNullable to keep their reset defaults. Cleared number inputs can yield null at runtime, so quantity and price explicitly include null. The form’s valid state does not narrow their TypeScript types. The submit method checks them rather than using a non-null assertion to silence the compiler. NonNullable changes reset behavior and type declarations; it is not input validation.

Connect the template and explain the bindings

<h2>Place an order</h2>
<form [formGroup]="orderForm" (ngSubmit)="submit()">
  <label for="ticker">Ticker</label>
  <input id="ticker" formControlName="ticker" aria-describedby="ticker-error" />
  @if (orderForm.controls.ticker.invalid && orderForm.controls.ticker.touched) {
    <p id="ticker-error" class="field-error">Enter a ticker.</p>
  }

  <label for="instrumentType">Instrument type</label>
  <select id="instrumentType" formControlName="instrumentType" aria-describedby="type-error">
    <option value="EQUITY">Equity</option><option value="BOND">Bond</option>
  </select>

    </p>
  }

  @if (orderForm.controls.price.invalid && orderForm.controls.price.touched) {
    <p id="price-error" class="field-error">
      {{ orderForm.controls.price.hasError('required') ? 'Price is required.' : 'Price must be at least 0.01.' }}
    </p>
  }

  <label for="side">Side</label>
  <select id="side" formControlName="side" aria-describedby="side-error">
    <option value="BUY">Buy</option><option value="SELL">Sell</option>
  </select>
  @if (orderForm.controls.side.invalid && orderForm.controls.side.touched) {
    <p id="side-error" class="field-error">Choose BUY or SELL.</p>
  }
  <button type="submit" [disabled]="pending()">{{ pending() ? 'Submitting...' : 'Submit order' }}</button>
  <button type="button" (click)="reset()" [disabled]="pending()">Reset form</button>
</form>
@if (error()) { <p class="api-error" role="alert">{{ error() }}</p> }
@if (lastOrder(); as response) {
  <p role="status">Order response received.</p>
  <pre>{{ response | json }}</pre>
}

[formGroup]="orderForm" connects the form element to the model. Each literal formControlName must match a group key exactly. It is not an HTML name attribute: the directive looks up a control. (ngSubmit) invokes your component handler through Angular’s form directive, including submission by Enter. Reactive form directives normally suppress native constraint validation unless you explicitly opt in with ngNativeValidate; the Angular validators drive this example.

The number input accessor converts entered numbers to numeric control values and an empty number input to null. step="any" permits decimal input at the HTML layer; Angular min validates the business input boundary. Labels, IDs and field-error descriptions still matter. @if decides when a message is rendered; interpolation displays text rather than inserting server HTML.

Reset and add/remove buttons need type="button", or a button inside a form defaults to submitting it. Keep Submit enabled for invalid fields so students can see markAllAsTouched reveal errors. Disable it while a request is pending to prevent repeated clicks.

05 / A fresh layer

Touched, dirty and validation are different states

StateMeaningUseful behavior
touched / untouchedUsually set on blur, or explicitly markedShow an invalid field after leaving it
dirty / pristineUser changed the value through the UITrack edits; programmatic setValue does not automatically mean dirty
valid / invalidValidation resultDecide whether a request may be sent
pendingAsync validation is runningWait for a completed validation result
disabledExcluded from validation and enabled parent valueDecide deliberately whether to submit that field

A default value can be valid and untouched. An empty field can be invalid and untouched. invalid && touched avoids shouting at people before they interact. On invalid submit, markAllAsTouched() marks descendants so every relevant message appears. It does not change values or repair errors.

06 / A fresh layer
getRawValue, value, patchValue and reset
For an enabled group, form.value omits disabled children, so typed group values can have optional keys. getRawValue() includes them. A fully disabled group is a special case: its value includes all children. The editor below models an enabled parent only. Including a disabled field is a submission policy choice, not a security guarantee.
orderForm.patchValue({ side: 'SELL', quantity: 999999 });
// Partial update; omitted controls keep their values.
orderForm.setValue({
  ticker: 'ULVR.L', instrumentType: 'EQUITY',
  quantity: 1, price: 40, side: 'BUY',
}); // Full shape required.
orderForm.controls.ticker.disable();
console.log(orderForm.value); // ticker omitted for an enabled group
console.log(orderForm.getRawValue()); // ticker included
orderForm.controls.ticker.enable();
orderForm.reset({ ticker: 'ULVR.L', instrumentType: 'EQUITY', quantity: 1, price: 40, side: 'BUY' });

07 / A fresh layer
Submission: validate, snapshot, call the service
  1. Ignore another submission while a request is pending.
  2. Require orderForm.valid. For the PDF’s synchronous enabled form, checking invalid is adequate; valid also protects against a future async PENDING state.
  3. Reveal invalid fields and return before the HTTP call.
  4. Read getRawValue, narrow nullable numbers, and pass the object to MissionApi.
  5. The service clears previous response/error, performs login then order, handles failures and clears pending in finalize.
Form validity is a snapshot at that moment, not a promise that the server will accept the order. The form knows the entered quantity; it does not authoritatively know the current holding or concurrent trades. Keep one request in flight, retain the inputs on failure, and offer a deliberate retry after examining the result.

Fallback service for students continuing directly from 10–11
import { Injectable, inject, signal } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { catchError, finalize, of, switchMap } from 'rxjs';
import { errorMessage } from './error-message';

export interface OrderRequest {
  ticker: string;
  instrumentType: 'EQUITY';
  quantity: number;
  price: number;
  side: 'BUY' | 'SELL';
}
// Subset of the course response. Match your server DTO before expanding it.
export interface OrderResponse {
  status: string;
  fee: number;
  newHoldingQuantity: number;
}
interface AuthResponse { accessToken: string; }
const AUTH_URL = 'http://localhost:3000/auth/login';
const MISSION_URL = 'http://localhost:8090/accounts/1/orders';

@Injectable({ providedIn: 'root' })
export class MissionApi {
  private readonly http = inject(HttpClient);
  readonly lastOrder = signal<OrderResponse | null>(null);
  readonly error = signal<string | null>(null);
  readonly pending = signal(false);

  submitOrder(order: OrderRequest): void {
    if (this.pending()) return; // one in-flight write in this classroom example
    this.pending.set(true);
    this.error.set(null);
    this.lastOrder.set(null);
    this.http.post<AuthResponse>(AUTH_URL, {
      username: 'alice', password: 'mission123', // classroom stand-in only
    }).pipe(
      switchMap(auth => {
        if (typeof auth.accessToken !== 'string' || !auth.accessToken) {
          throw new Error('Login response did not contain an access token');
        }
        return this.http.post<OrderResponse>(MISSION_URL, order, {
          headers: { Authorization: `Bearer ${auth.accessToken}` },
        });
      }),
      catchError((error: unknown) => {
        this.error.set(errorMessage(error));
        return of(null);
      }),
      finalize(() => this.pending.set(false)),
    ).subscribe(response => {
      if (response !== null) this.lastOrder.set(response);
    });
  }
}
08 / A fresh layer
Read the real server error and keep its contract clear
import { HttpErrorResponse } from '@angular/common/http';
export function errorMessage(error: unknown): string {
  if (error instanceof HttpErrorResponse) {
    const body = error.error as { message?: unknown } | null;
    if (typeof body?.message === 'string') return body.message;
    if (error.status === 0) return 'Could not reach the service. Check the server, network and CORS.';
    return error.message;
  }
  return error instanceof Error ? error.message : 'Unexpected request failure';
}
HttpErrorResponse.message is Angular’s wrapper description. Its error property holds the response body, which can be parsed JSON, text, a browser error event or another representation. For the supplied curated JSON contract, error.error?.message finds the business reason. Optional chaining tolerates null/undefined; ?? chooses the fallback only for null/undefined. Checking the property is actually a string is more robust than assuming every server returns the same shape.
Status 0 can mean network, CORS or another client-side delivery failure. The UI cannot infer which one merely from 0, and absence of a response does not prove an order was never committed. Preserve state and reconcile before resubmitting writes.
The course’s GlobalExceptionHandler deliberately returns short public messages. Keep stack traces, SQL, paths and secrets out of API responses at the server. Rendering text safely prevents HTML injection but does not make a sensitive message safe to disclose. Do not try to detect secrets with a browser string filter.

Dynamic structures: FormArray for a picnic guest list
import { Component, inject } from '@angular/core';
import { FormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
@Component({
  selector: 'app-picnic-guests', standalone: true, imports: [ReactiveFormsModule],
  template: `
    <form [formGroup]="picnic">
      <div formArrayName="guests">
        @for (control of guests.controls; track control; let i = $index) {
          <label>Guest {{ i + 1 }} <input [formControlName]="i" /></label>
          @if (control.invalid && control.touched) { <p>Enter a guest name.</p> }
          <button type="button" (click)="remove(i)">Remove</button>
        }
      </div>
      <button type="button" (click)="add()">Add guest</button>
    </form>
  `,
})
export class PicnicGuests {
  private readonly fb = inject(FormBuilder);
  protected readonly guests = this.fb.array([
    this.fb.nonNullable.control('Raccoon', Validators.required),
    this.fb.nonNullable.control('Beaver', Validators.required),
  ]);
  protected readonly picnic = this.fb.group({ guests: this.guests });
  protected add(): void { this.guests.push(this.fb.nonNullable.control('', Validators.required)); }
  protected remove(index: number): void { this.guests.removeAt(index); }
}
A FormGroup has named keys. A FormArray has ordered child controls whose number can change. Use push, removeAt and clear on the FormArray API, so Angular registers children and recalculates state. Avoid manually splicing its controls array. Track each control object in @for to preserve identity when removing rows; the numeric index still tells formControlName where it is now.
Each guest is required, but an empty array has no invalid child and can be valid. Add an array-level validator if the picnic requires at least one guest. A nested group can model address fields; a FormArray of groups can model multiple orders. Keep the core lab as one order and one submission before extending it.

valueChanges and custom validation: useful extensions
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { AbstractControl, ValidationErrors } from '@angular/forms';

// Inside the component constructor, an injection context:
this.orderForm.valueChanges.pipe(takeUntilDestroyed()).subscribe(value => {
  console.log('Form snapshot', value); // do not log credentials
});

// A reusable synchronous validator:
export function trimmedRequired(control: AbstractControl): ValidationErrors | null {
  return typeof control.value === 'string' && control.value.trim().length > 0
    ? null : { trimmedRequired: true };
}
valueChanges is a stream of model changes, not automatic submission. Use subscription cleanup for long-lived streams; takeUntilDestroyed is suitable in an injection context. Child control emissions may occur before a parent snapshot has updated, so subscribe to the parent when you need the entire group. Enabling/disabling a control can emit too.
Async validators can check remote information and put a form into PENDING. Those checks improve feedback but can become stale; the order endpoint must still validate at commit time. Never auto-submit a BUY on every valueChanges emission. For previews or lookups, debounce and cancel stale reads; order writes need deliberate submission.

Model answers: explain the evidence
The positive-quantity checks overlap, yet server validation is still mandatory because the UI can be bypassed. The holdings limit is an additional state-dependent rule. TypeScript types do not validate incoming HTTP JSON. markAllAsTouched changes presentation state, not correctness. A business rejection can contain curated JSON; a network failure may have no such body, so optional chaining and a fallback prevent a second error in error handling.
A failed SELL should leave the holding unchanged when the backend transaction rejects it correctly. Show before/after SQL results and the rejection response. A network failure has an uncertain write outcome, so it is not equivalent to a confirmed business rejection.
