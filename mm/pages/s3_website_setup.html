Bonus lab · Amazon S3

Put your website on S3.

Beaver packs the files. Raccoon checks the bucket name. Narwhal tests the links. Publish this HTML course as a simple public static website.

Build your bucket policy ↓

For public teaching files only. The policy below lets anyone read every object in this bucket. Use a dedicated website bucket with no secrets, personal data or private files. This page generates text locally; it does not change AWS settings.

1. Choose a bucket name and create it

Open the S3 console, choose Create bucket, use a General purpose bucket in the standard shared global namespace, and choose your lab Region. Keep Object Ownership: Bucket owner enforced, with ACLs disabled.

A simple format is project-purpose-unique-suffix, for example maple-ui-yourname-7f3a. Replace “yourname” and the suffix. Prefer lowercase words separated by hyphens. Do not paste an s3:// URL, website URL or ARN into the name field.

Names in this namespace must be unique across AWS accounts and Regions within an AWS partition. Format validation cannot check availability; Create bucket confirms it. This lesson targets ordinary commercial AWS Regions and uses arn:aws:.

2. Enter your name and generate the policy

  • Use 3–63 characters.
  • Use lowercase letters, numbers, hyphens or periods.
  • Start and end with a letter or number.
  • No consecutive periods.
  • No IP-address-style names.
  • Avoid reserved names.

Periods are allowed here, but a hyphen-only name is simpler. S3 Transfer Acceleration does not support names containing periods.

Reserved prefixes and suffixes

For this shared-global-namespace checker, do not start with xn--, sthree- or amzn-s3-demo-. Do not end with -s3alias, --ol-s3, .mrap, --x-s3, --table-s3 or -an. The -an suffix belongs to the separate account regional namespace, which this beginner setup does not use.

Live bucket policy

The Resource updates as you type. Copy only after the name matches the bucket you created.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": [
        "arn:aws:s3:::maple-ui-yourname-7f3a/*"
      ]
    }
  ]
}

Principal: "*" means everyone. s3:GetObject allows reading objects. The trailing /* selects the bucket’s objects. This policy does not grant uploads, deletion or listing. Paste it into this bucket’s Bucket policy editor, not an IAM user policy.

3. Enable static website hosting

  1. Open your bucket → Properties.
  2. Find Static website hosting → Edit.
  3. Choose Enable and Host a static website.
  4. Set Index document to index.html, exactly matching the file’s case.
  5. Save changes. An error document is optional; enter 404.html only if you also upload that file.

4. Allow public read access

  1. Go to Permissions → Block public access (bucket settings) → Edit.
  2. For this public website bucket, clear Block all public access, save, and acknowledge the confirmation.
  3. Under Bucket policy → Edit, paste the generated JSON for your exact bucket, then save.

Account-level settings can still block this bucket. AWS applies the most restrictive effective settings. If your classroom account blocks public policies, ask the instructor or administrator to resolve that restriction; do not change account-wide settings casually.

Keep ACLs disabled for this new bucket. Bucket owner enforced ownership lets the bucket policy manage object access. The older ACL section of the documentation applies to different ownership setups and is not needed for this lab.

5. Upload the extracted website files

Extract the course ZIP first. Upload its contents, not the ZIP and not an extra enclosing folder. Put index.html at the bucket root. Keep the folders and filenames intact:

  • pages/ contains the lessons.
  • assets/ contains the images, styles and scripts.
  • labs/ and resources/ keep the course downloads working.

Uploading only index.html leaves broken links and missing graphics. S3 serves static files; it does not run Node.js, Angular’s development server or Spring Boot. The lab source files remain downloads.

6. Open the website endpoint and test

In Properties → Static website hosting, open the Bucket website endpoint. Use the endpoint shown by AWS rather than guessing its Region-specific format. Test Home, a lesson, its hero/footer images and a lab download.

This direct S3 website endpoint uses HTTP. If you later need HTTPS with a private bucket, use CloudFront with origin access control and an S3 REST origin. That is a separate setup; this page keeps the public-bucket lab simple.
