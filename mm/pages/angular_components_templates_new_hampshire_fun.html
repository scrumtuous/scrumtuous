03 / A fresh layer

A standalone component has its own template vocabulary

A component combines a class holding state and behavior, metadata telling Angular how to use it, a template describing the view, and styles for that view. Standalone means its template dependencies are imported directly into the component.

@Component({
  selector: 'app-holdings-summary',
  standalone: true,
  imports: [DecimalPipe],
  templateUrl: './holdings-summary.html',
  styleUrl: './holdings-summary.css',
})

The TypeScript import at the top of a file makes DecimalPipe a usable symbol in that file. The metadata imports array makes the pipe available to this component’s template. These two imports do different jobs. Modern @for/@empty syntax is built into the template language and does not require NgFor or CommonModule.

Standalone is the default in modern Angular; writing standalone: true explicitly is still clear and valid for this lesson. It does not make the component global. The parent imports it to use its selector. Merely exporting the class does not register its element everywhere.

Component styles use Angular’s default emulated encapsulation unless you change it. This scopes styles through generated attributes; it is not automatically native Shadow DOM.
04 / A fresh layer

Read every piece of the Holding state

The interface names a data shape. Each row has a ticker string, a quantity number, and a unit price number. Holding has no Angular behavior by itself. It is erased when TypeScript compiles and does not validate incoming JSON.

interface Holding {
  ticker: string;
  quantity: number;
  price: number;
}
protected readonly holdings = signal<Holding[]>([
  { ticker: 'ULVR.L', quantity: 500, price: 42.1 },
  { ticker: 'AZN.L', quantity: 120, price: 108.5 },
]);
TokenMeaning
protectedThe member is intended for this class, subclasses and its Angular template; ordinary external TypeScript cannot directly access it.
readonlyThe field reference cannot be reassigned. It does not freeze the array inside or forbid holdings.update(...).
signal<Holding[]>Create a writable signal whose current value is an array of Holding objects. The generic types the value.
holdings()Call the signal getter to read the current array. It is not a setter and does not copy the array.
holdings.set(next)Replace the stored value.
holdings.update(callback)Pass the current value to a callback and use its return value as the proposed next value.

The stable signal wrapper is the reactive address. Its internal array is the value at that address. Keep the address and replace the array when contents change. A plain array declaration supplies data but does not provide signal dependency notifications.

What does readonly actually stop?

Which is invalid: holdings.update(...), or assigning a new signal to this.holdings? Does readonly stop push?

Reveal solution and reasoning

Reassigning the readonly field is invalid. update remains allowed. readonly on the field does not stop push on the mutable array it contains. You can choose readonly array types for stronger compile-time discipline, but still need correct immutable updates.

05 / A fresh layer

Reduce the holdings into one derived total

The only stored facts are the rows. The total is a calculation over those facts. computed gives that calculation a cached reactive value, so every mutation method does not need its own total-recalculation code.

protected readonly totalValue = computed(() =>
  this.holdings().reduce(
    (sum, h) => sum + h.quantity * h.price, 0,
  ),
);

The arrow passed to computed is a recipe. When Angular needs totalValue(), it runs the recipe if its cache is absent or invalid. The holdings() read happens in this reactive calculation, so Angular records a dependency on holdings. An ordinary read outside a reactive context does not automatically subscribe that caller.

reduce visits each row and carries an accumulator. The initial accumulator is 0. For each holding, multiply units by unit price, then add that row’s value to the running sum. Returning the new sum supplies the accumulator for the next row.

StepArithmeticRunning sum
Initial value00
ULVR.L500 × 42.1 = 21,05021,050
AZN.L120 × 108.5 = 13,02034,070
After BP.L200 × 4.8 = 96035,030

The initial 0 also makes an empty list return 0 instead of failing. computed is lazy: the first read evaluates it. Repeated reads without an effective dependency change reuse the cached value. A changed dependency invalidates it; the next read computes a fresh result. “Automatically updates” does not mean eagerly calculating after every instruction.

// Equivalent plain loop, useful while learning reduce:
let sum = 0;
for (const h of holdings()) {
  sum = sum + h.quantity * h.price;
}
// A computed can contain this loop and return sum too.
JavaScript numbers use binary floating point. This lesson’s simple arithmetic teaches reactivity. Real financial systems need a deliberate money representation, rounding policy and currency model; the number pipe only formats display.
06 / A fresh layer

A template is a description, not a string you append

HTML still supplies the list, items, buttons and paragraph. Angular adds interpolation, event and property bindings, control-flow blocks, and pipes. These expressions execute in the component’s template context.

Angular creates and updates DOM for this description. You do not manually select li elements or set total.textContent in the real component. Interpolation renders text, not arbitrary HTML markup. The teaching models below manually render DOM solely to expose the mechanisms without an Angular build.

The template’s Add button is deliberately disabled when BP.L already exists. The slide’s unconditional append would produce duplicate tickers on repeated clicks; with track holding.ticker, that is a separate identity bug. The model solution guards the duplicate as well as disabling the button.

07 / A fresh layer

Track identity; do not confuse it with reactivity

@for iterates the current array and creates a view for each row. track holding.ticker tells Angular which logical row corresponds to which view across updates, so a stable row can retain its DOM identity.

Tracking does not notify a signal, invalidate a computed, or make a mutating update immutable. It answers “which row is this?” after the view is being checked. Signal equality answers “did the source value change?” Those are different questions.

@for (holding of holdings(); track holding.ticker; let i = $index) {
  <li>{{ i + 1 }}. {{ holding.ticker }}</li>
} @empty {
  <li>No holdings.</li>
}

Use ticker only if each ticker is unique and stable. An interface alone does not enforce uniqueness. If the domain permits several lots of BP.L, give each row a stable id and track holding.id instead. $index is appropriate for genuinely static collections; it is a poor identity when rows are inserted, removed or reordered.

Filtering by ticker removes every matching ticker. If you need to remove one lot, use the lot’s unique id. The @empty li is a message, not a holding: do not mistake the number of li elements for the number of data rows when the list is empty.

Why not append BP.L forever?

What happens if three rows all use the same tracked BP.L key?

Reveal solution and reasoning

The key is ambiguous. Angular can report duplicate-key diagnostics and view reuse may become inefficient or confusing. Guard one row per ticker or use unique lot ids. Do not use this key problem as your proof of the equality/cache bug; isolate the bugs.

08 / A fresh layer

The number pipe changes presentation, not state

DecimalPipe is imported from @angular/common and added to the standalone component’s imports. Its template name is number. The vertical bar applies a pipe; the colon supplies its argument.

import { DecimalPipe } from '@angular/common';
// @Component({ imports: [DecimalPipe], ... })
// Template:
<p>Total: {{ totalValue() | number: '1.2-2' }}</p>

Read 1.2-2 as a minimum of one integer digit, minimum two fractional digits, and maximum two fractional digits. With the default en-US locale, 34070 becomes 34,070.00 and 4.8 becomes 4.80. Grouping and decimal characters depend on the locale. This is not a currency conversion and adds no currency symbol.

The raw total remains a number. Formatting returns display text. If the number input is stale, the pipe neatly formats the stale number; formatting cannot repair a dependency bug. Missing DecimalPipe in imports commonly produces a template error about the unavailable number pipe.

09 / A fresh layer
Correct add and remove: return a new array
update does not magically make a mutation reactive. Its callback must supply a next value that the equality comparison recognizes as different. For arrays, produce a new array reference.
protected addHolding(): void {
  this.holdings.update(current => [
    ...current,
    { ticker: 'BP.L', quantity: 200, price: 4.8 },
  ]);
}
  1. Angular passes the current array to the callback.
  2. [...] creates a new array object.
  3. ...current copies the existing row references into it in their order.
  4. The new BP.L object is appended.
  5. The callback returns the new array; it does not push into the old one.
  6. Object.is(newArray, oldArray) is false, so the signal reports a change and invalidates dependent computed values.
Spread is a shallow copy. It copies the array container, not deeply cloned rows. That is sufficient for adding a new row. Editing an existing object needs a new object for that row too.
protected removeHolding(ticker: string): void {
  this.holdings.update(current =>
    current.filter(h => h.ticker !== ticker));
}
// Update a row: replace both the container and changed object.
this.holdings.update(current => current.map(h =>
  h.ticker === "ULVR.L" ? { ...h, quantity: h.quantity + 10 } : h
));
filter creates a new array of the rows that pass the test. It does not delete elements from the original array. Each retained row is the same row object. map creates a new array; the object spread in the changed branch creates a new edited row.

10 / A fresh layer
Deliberately wrong: the same-reference update
Now replace the immutable callback with the slide’s broken version. Do this temporarily in your own lab, observe it, and restore the correct code.
protected addHolding(): void {
  this.holdings.update(current => {
    current.push({ ticker: 'BP.L', quantity: 200, price: 4.8 });
    return current; // exactly the same array object
  });
}
current.push modifies the existing array object. It returns the new length, but this callback ignores that return and returns current instead. current and the signal’s old array still point to the exact same object.
const oldArray = holdings();
oldArray.push(newHolding);
const proposedNext = oldArray;
console.log(Object.is(proposedNext, oldArray)); // true
// Array contents changed. Array identity did not.
Angular’s default signal equality is Object.is. It does not walk the array and compare its contents with an earlier snapshot. Returning the same object means no signal change notification. update was called, but an effective signal change did not occur.
The initial computed total was already read by the template and cached at 34,070. Its dependency has not reported a change, so the next totalValue() read can reuse that cache. A fresh direct reduce over holdings() would see the mutated contents and return 35,030. The cached computed is not that fresh direct calculation.
QUIZ ALERTThe supplied multi-select question asks about this exact mismatch. The relevant reasons are unchanged reference identity, a template refresh seeing live array contents, and the immutable remedy. Neither push nor update automatically throws, and computed is not permanently limited to one execution.
If a computed has never been read before the mutation, its first calculation may see the new contents. Cache it first when reproducing this exercise. Otherwise you are testing a different sequence.
11 / A fresh layer
Why the list can change while the total does not
A template refresh and a computed-cache invalidation are separate mechanisms. The visible list can get a fresh view of the array while the total receives an old cached result.
StageDirect list readComputed total read
Initial renderReads the two live rows.Calculates 34,070 and caches it.
Mutating handlerpush adds a row to that same array.No dependency invalidation from unchanged identity.
View refresh@for reads holdings() and sees the added row.totalValue() returns its still-valid-by-notification cache.
Immutable repairA new array is stored and rendered.Dependency is invalidated; next read calculates the new total.
The slide’s Zone.js setup
In a Zone.js-configured application, patched events and asynchronous tasks can cause Angular to synchronize views even if no signal value was reported changed. On an eligible template refresh, @for reads the live mutated array. View eligibility and scheduling still depend on the change-detection strategy and configuration. “Every DOM event checks everything” is too broad: events outside Angular’s zone and skipped subtrees matter.
The Angular 21 course setup
Angular 21+ defaults to zoneless. It does not depend on Zone.js observing every task. Angular recognizes notifications such as a bound template listener or a changed signal used in a template. The (click) handler itself can cause this component’s view to refresh even when the mutation fails the signal equality check. That can produce the same list/total mismatch without Zone.js.
By contrast, arbitrary background work that mutates an array without a recognized notification may leave the whole view unchanged until a later refresh. The mutation bug is the missing signal notification; which UI pieces visibly change also depends on what schedules and checks that view.
// Bound template event:
// click → handler → eligible view refresh
//   @for reads current mutable contents
//   computed getter returns cache unless invalidated

// Correct source update:
// new array → unequal identity → signal notification
//   dependent computed invalidated
//   next totalValue() read calculates current sum

12 / A fresh layer
Keep one source of truth, and repair every path
Making totalValue a writable signal(0) and setting it by hand is tempting. Then add, remove, edit, reset and HTTP-load paths must all remember to update it correctly. Missing just one produces an inconsistent portfolio. computed keeps the derivation in one place, provided the sources use proper reactive updates.
// Fragile: two separate writable facts to keep synchronized.
protected readonly holdings = signal<Holding[]>([]);
protected readonly totalValue = signal(0);
// add updates both; remove forgets total; state drifts.

// Preferred: rows are facts; total is a recipe.
protected readonly totalValue = computed(() =>
  this.holdings().reduce((sum, h) => sum + h.quantity * h.price, 0)
);
protected and readonly do not solve that synchronization problem. A readonly field can hold a writable signal. An asReadonly view removes the signal’s public set/update API but does not deep-freeze its array. A computed is read-only because it is derived, not because the class field happens to use readonly.
Do not “fix” the broken computed by adding a manual reduce in the template, forcing more change-detection passes, or copying totals with an effect. Restore immutable source updates. A later correct new-array update may appear to heal the old bug by invalidating the cache, but it does not make the earlier mutation safe.
QUIZ ALERTThe supplied single-choice question asks why manually maintained totalValue can drift from holdings. The risk is duplicated writable state. It is not a restriction on readonly fields, signal rendering or number pipes.
Find the hidden object mutation
Is this safe: holdings.update(rows => { rows[0].quantity++; return rows; })? Write the repair.

  i === 0 ? { ...h, quantity: h.quantity + 1 } : h

The broken callback mutates a nested object and returns the same container. Replace the array and the changed object. Review reset, load and edit methods too.

Complete holdings-summary.ts solution
import { Component, computed, signal } from '@angular/core';
import { DecimalPipe } from '@angular/common';

interface Holding {
  ticker: string;
  quantity: number;
  price: number;
}

@Component({
  selector: 'app-holdings-summary',
  standalone: true,
  imports: [DecimalPipe],
  templateUrl: './holdings-summary.html',
  styleUrl: './holdings-summary.css',
})
export class HoldingsSummary {
  protected readonly holdings = signal<Holding[]>([
    { ticker: 'ULVR.L', quantity: 500, price: 42.1 },
    { ticker: 'AZN.L', quantity: 120, price: 108.5 },
  ]);

  protected readonly totalValue = computed(() =>
    this.holdings().reduce(
      (sum, h) => sum + h.quantity * h.price, 0,
    ),
  );
  protected readonly hasBP = computed(() =>
    this.holdings().some(h => h.ticker === 'BP.L'),
  );

  protected addHolding(): void {
    this.holdings.update(current => current.some(h => h.ticker === 'BP.L')
      ? current
      : [...current, { ticker: 'BP.L', quantity: 200, price: 4.8 }]);
  }

  protected removeHolding(ticker: string): void {
    this.holdings.update(current =>
      current.filter(h => h.ticker !== ticker));
  }
}
