01 / A fresh layer

HTML is the structure

Raccoon wants pancakes. Beaver wants pancakes. Before either can order, someone must build the breakfast club login page. HTML gives the heading, form, labels, and button their places and meaning.

HTML

Structure and content: a heading, paragraph, link, input, or form.

CSS

Presentation: maple gold, spacing, layout, and type. That is Module 02.

JavaScript

Behavior: responding to events and calling an API. That comes next.

HyperText Markup Language describes a document. “HyperText” points to links between documents. A browser parses HTML into a document tree, then renders it. HTML is a markup language, rather than a language for writing algorithms.

02 / A fresh layer

Tags, elements, and pancake nesting

An opening tag marks the beginning, a closing tag marks the end, and the content goes between them. Together they form an element.

<h1>Maple Syrup Mission Control</h1>
<!-- Opening tag + content + closing tag = one element -->

Elements can contain other elements. Close the inner element before closing the outer one. This parent/child structure becomes the DOM, the Document Object Model that JavaScript will later read and change.

html: the root
body
header → h1
main → form → label + input + button
footer → p
<main>
  <form>
    <label for="username">Username</label>
    <input id="username">
  </form>
</main>
The Pancake PlaygroundEdit · Run · Observe

Swap a tag, keep the words

Change h1 to p in both tags. Run it. Then restore the heading and add an h2 for “Breakfast orders.” What changed?

Reveal solution and reasoning

The browser’s default styling changes, but the more important change is meaning: a paragraph is no longer a heading. h1 names the main topic; h2 introduces a subsection. Do not choose heading levels merely to get a font size.

03 / A fresh layer

Small tags, useful attributes

Void elements such as input, img, meta, and br do not wrap content and have no closing tags. Do not write </input>. A trailing slash in HTML, such as <input />, does not make the element behave differently.

<!-- A note for humans; it is not rendered as page text. -->
<input type="text" id="username" name="username" required>
<img src="pancakes.jpg" alt="Pancakes topped with maple syrup">
<br>
AttributeWhat it does
typeChooses an input behavior, such as text or password.
idIdentifies an element. Keep it unique within the document.
nameProvides the field key when a form is submitted.
requiredA boolean attribute: its presence enables the requirement.
minlength="3"Sets a minimum length for a nonempty text value.
Watch the syrup trap: required="false" still means required. Remove the attribute to turn it off. Comments do not appear as rendered text, but anyone can see them in source. They are not a hiding place for passwords.
04 / A fresh layer

Your first real document

Create index.html in a plain-text editor. Save it, then double-click it or drag it into a browser. These first two labs need no npm, compiler, or server.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mission Control - Login</title>
</head>
<body>
<header><h1>Mission Control</h1></header>
<main>
  <form id="login-form">
    <h2>Log In</h2>
    <div class="field">
      <label for="username">Username</label>
      <input type="text" id="username" name="username"
             autocomplete="username" required minlength="3">
    </div>
    <div class="field">
      <label for="password">Password</label>
      <input type="password" id="password" name="password"
             autocomplete="current-password" required minlength="8">
    </div>
    <button type="submit">Log In</button>
  </form>
</main>
<footer><p>LEAP Mission Control</p></footer>
</body>
</html>
Line or regionReason it exists
<!DOCTYPE html>Selects modern standards mode; it is a declaration, not a page element.
<html lang="en">The root, with the language used by assistive and translation tools.
headDocument metadata. The title appears in the browser tab; it is not a body heading.
charsetUTF-8 handles text such as “Québec” consistently.
viewportHelps mobile layouts use the device width, ready for Module 02.
bodyContains the page content users interact with.

View Page Source shows the original markup delivered to the browser. Inspect shows the current live DOM, which the browser may have repaired and JavaScript may have changed. Save your file and reload to check changes outside this playground.

05 / A fresh layer

A real input beats a disguised div

Beaver builds a proper form. Raccoon paints a box and calls it a form. They may look alike, but their built-in behavior differs.

Bad version: div soup

<div>Username</div>
<div contenteditable="true"></div>
<div>Log In</div>

The editable div can accept text, but it is not a native form field. The label is not associated, and the last div is not a keyboard-operable submit button.

Fix: native semantics

<label for="username">Username</label>
<input id="username" name="username" required minlength="3">
<button type="submit">Log In</button>

The control participates in a form. It gets native focus and editing behavior, label association, and constraint validation.

Use header, main, and footer for the page regions. Use button for an action and a for navigation. A div is useful when you need a neutral grouping, such as a field wrapper.

QUIZ ALERTSprint 9 question 1 asks why actual inputs matter. The central reason is native form behavior and accessibility, rather than rendering speed or search-engine bans. A custom control can recreate some behaviors with work; a styled contenteditable div does not gain them automatically.

Prove it beyond appearance

Use Tab to reach each control, press Enter on the submit button, and click the label. In DevTools, inspect the accessibility information for the native input. Compare it with an editable div.

Reveal solution and reasoning

A labeled input should expose a meaningful control role and accessible name, such as textbox “Username.” The password field masks typed characters. A generic div does not automatically expose the same semantics or enforce input constraints. Exact accessibility-tree wording varies by browser.

06 / A fresh layer

Labels and native validation

for on a label matches the input’s id. The input’s name is the submitted field key, a different job. Clicking a correctly connected label focuses its control.

required rejects an empty value. minlength rejects a too-short nonempty value. They belong together here: minlength alone does not make an optional field mandatory.

Beaver’s form inspection stationEdit · Run · Observe
  1. Submit with both fields empty. Read the browser’s message.
  2. Type ab into the username and submit. The minimum is three characters.
  3. Use maple and a password of at least eight characters. The preview reports a successful local validation.
  4. Click “Username.” Focus should land in its input.
  5. Change for="username" to for="raccoon", run it, and repeat. Repair the mismatch.
This playground intercepts a valid submit only to prevent navigation and show a demo message. The browser still performs the native constraint checks. Use typed input for the minlength test. This does not authenticate anyone. Do not type real passwords into teaching examples. A password input masks characters; it does not encrypt them. A real login uses HTTPS and an appropriate POST endpoint. The default form method is GET, which can place submitted field values in the URL. Downloaded lab examples demonstrate markup only, not a real login flow.
QUIZ ALERTClient-side checks help users correct mistakes. They can be bypassed, so a real backend must validate independently. This connects to the later Sprint 9 question about keeping server-side quantity validation.

Quick stack check

A username has minlength="3" but no required attribute. What happens if it is empty?

Lab 01: assemble Mission Control

Use the pancake story while practicing, then keep the original lab’s exact heading and tagline for your hand-in. The supplied lab starts blank because the real content is still inside comments.
