Concept 2

Nouns and Verbs: The Simplest Starting Technique

Underline nouns as candidate classes or attributes. Underline verbs as candidate responsibilities. This gives you a starting list to discuss.

The psychology class wants to present two shapes to a student.
Each shape has dimensions and can calculate its area.
The experiment should compare the two areas and record the student's judgement.
The first iteration includes Square, Rectangle, Circle, Triangle, Line, and Point.
Noun candidate thing Verb candidate responsibility Possible attribute
Do not over-trust the technique: not every noun becomes a class, and not every class appears as a noun. Nouns and verbs generate candidates, not final answers.

Concept 3

Class or Just an Attribute?

A class usually has its own identity, behavior, or lifecycle. An attribute is usually just a value that belongs to some other object.

Candidate Likely choice Reasoning
Circle Class It has dimensions and behavior such as calculating area.
radius Attribute It is a value belonging to Circle.
Experiment Maybe a class It may coordinate shape presentation, comparison, and result recording.
area Usually not its own class It can be calculated from a shape's dimensions.
Judgement Ambiguous Could be a simple value, or could become a richer result object if later requirements grow.
Beginner test
Ask: does this thing do something or need to be tracked individually? If yes, a class becomes more plausible. If it is simply a value describing another object, an attribute becomes more plausible.
Direct quiz connection: class-versus-attribute decisions are often ambiguous. The correct response is not to insist there must be one objectively correct model. Record the alternatives and the reasoning.

💖 Quick check

Would you make radius its own class in the first MadShapes model, or an attribute of Circle? Why?

I would make radius an attribute of Circle.

It is a simple value describing the Circle, with no separate identity or behavior needed in this iteration.
Concept 4

Assigning Responsibilities

For every verb, ask: whose job is this really? Good object models put behavior near the data and rules it belongs to.

Reasonable ownership

  • Shape: calculate its area
  • Experiment: coordinate a comparison
  • StudentResponse: store a judgement
  • ResultRecorder: record the outcome, if such a class is actually needed

Suspicious ownership

  • ShapeManager: calculate all areas
  • ShapeManager: compare all shapes
  • ShapeManager: record all answers
  • ShapeManager: decide everything
🚨 The mega-manager smell
calculate()
compare()
validate()
record()
display()
persist()

Why be suspicious?

When nearly every verb ends up on one central manager class, the other objects become passive data holders.

You will formally name this smell later when SOLID introduces the Single Responsibility Principle.

Quiz connection: if almost every responsibility gets dumped into one central manager, be suspicious of a God class design smell.

Concept 6

There Is No Single Correct First Draft

Two thoughtful teams can produce different models from the same requirements. The goal is not identical diagrams. The goal is a defensible model.

Is Experiment a class?

Option A: yes, because it coordinates trials and may own rules.

Option B: maybe not yet, if another class already owns that coordination.

Is Judgement a class?

Option A: a String or enum attribute is enough.

Option B: make it a result object if more response metadata is coming.

Are Line and Point shapes?

For area comparison, both produce area 0. That may be useful, odd, or a hint that the hierarchy deserves review later.

Direct quiz connection: when reasonable people disagree about class vs attribute, write down both views and the reasoning. That disagreement becomes useful input for peer review.
ROFLGator peer-review preview If two teams disagree, the useful question is not "who is wrong?" It is "what requirement or design assumption made you choose that?"
