The Mutable Default Argument Trap

Why a list, dictionary, set, or nested object can mysteriously remember previous function calls — and the simple None pattern that fixes it.

📋 Lists 🗂️ Dicts 🧺 Sets 🏗️ Methods 🪆 Nested Data 📝 Quiz Alert
Module objectives

By the end, you'll understand...

🚨 The bugWhy mutable defaults can keep state between function calls.
🧪 How to prove itTest repeated calls and even compare object identities with id() or is.
✅ The fixUse None as the default and create a fresh object inside the function.
If you see def f(x, values=[]), {}, or set() in a default parameter, be suspicious.
The core idea

Why This Happens

Python evaluates default argument values when the function is defined — not every time the function is called.

def add_passenger(name, passengers=[]):
    passengers.append(name)
    return passengers
1️⃣ Define[] is created once.
2️⃣ CallRose is appended.
3️⃣ CallThe same list is reused.
4️⃣ MutateJack is appended too.
5️⃣ SurpriseOld data remains.
QUIZ ALERT
The default list is created once when the function is defined. Every call that omits the argument can reuse and mutate that exact same object.
Example 1

A List That Remembers Previous Calls

🚫 Bad version

def add_passenger(name, passengers=[]):
    passengers.append(name)
    return passengers

Test it

print(add_passenger("Rose"))
print(add_passenger("Jack"))
print(add_passenger("Molly"))

Bad result

['Rose']
['Rose', 'Jack']
['Rose', 'Jack', 'Molly']

✅ Fix

def add_passenger(name, passengers=None):
    if passengers is None:
        passengers = []

    passengers.append(name)
    return passengers

Test again

print(add_passenger("Rose"))
print(add_passenger("Jack"))
print(add_passenger("Molly"))

Proper result

['Rose']
['Jack']
['Molly']

🌸 Quick check

Why did Jack's original bad result still include Rose?

Because both calls reused the same default list object.
Example 2

A Dictionary That Changes Earlier Results

🚫 Bad version

def passenger_info(name, info={}):
    info["name"] = name
    return info

Test it

rose = passenger_info("Rose")
jack = passenger_info("Jack")

print(rose)
print(jack)
print(rose is jack)

Bad result

{'name': 'Jack'}
{'name': 'Jack'}
True
Why did Rose change? Both variables point to the same dictionary. The second call overwrote the "name" key inside that shared object.

✅ Fix

def passenger_info(name, info=None):
    if info is None:
        info = {}

    info["name"] = name
    return info

Proper result

{'name': 'Rose'}
{'name': 'Jack'}
False
QUIZ ALERT
rose is jack returning True proves both names refer to the exact same object.
Example 3

A Set of Warnings That Keeps Growing

🚫 Bad version

def add_warning(warning, warnings=set()):
    warnings.add(warning)
    return warnings

Test it

print(add_warning("HIGH_FARE"))
print(add_warning("CHILD"))

Bad result

{'HIGH_FARE'}
{'HIGH_FARE', 'CHILD'}

✅ Fix

def add_warning(warning, warnings=None):
    if warnings is None:
        warnings = set()

    warnings.add(warning)
    return warnings

Proper result

{'HIGH_FARE'}
{'CHILD'}

🧺 Quick check

Why is set() dangerous as a default even though it does not use square brackets?

Because a set is mutable too.

Its contents can change after the object is created.
Example 4

Methods Have the Same Problem

Putting the function inside a class does not change the rule.

🚫 Bad version

class PassengerService:

    def add_note(self, note, notes=[]):
        notes.append(note)
        return notes

Test with two objects

service1 = PassengerService()
service2 = PassengerService()

print(service1.add_note("Rose"))
print(service2.add_note("Jack"))

Bad result

['Rose']
['Rose', 'Jack']
Surprise: even two different PassengerService instances can reuse the same default list because the default belongs to the method's function definition.

✅ Fix

class PassengerService:

    def add_note(self, note, notes=None):
        if notes is None:
            notes = []

        notes.append(note)
        return notes

Proper result

['Rose']
['Jack']
QUIZ ALERT
Mutable default arguments are a function-definition problem, not just a standalone-function problem. Methods can have the exact same bug.
Example 5

Nested Mutable Data Makes It Worse

🚫 Bad version

def create_manifest(
    name,
    manifest={"passengers": []}
):
    manifest["passengers"].append(name)
    return manifest

Test it

manifest1 = create_manifest("Rose")
manifest2 = create_manifest("Jack")

print(manifest1)
print(manifest2)
print(manifest1 is manifest2)

Bad result

{'passengers': ['Rose', 'Jack']}
{'passengers': ['Rose', 'Jack']}
True
Nested mutation: the dictionary is shared, and the list inside that dictionary is shared too.

✅ Fix

def create_manifest(name, manifest=None):
    if manifest is None:
        manifest = {
            "passengers": []
        }

    manifest["passengers"].append(name)
    return manifest

Proper result

{'passengers': ['Rose']}
{'passengers': ['Jack']}
False
How to prove it

Use id() to Catch the Shared Object

🚫 Bad default

def add_passenger(name, passengers=[]):
    print(id(passengers))
    passengers.append(name)
    return passengers

add_passenger("Rose")
add_passenger("Jack")
add_passenger("Molly")

You may see the same object ID three times:

140312841284672
140312841284672
140312841284672

✅ Fixed version

def add_passenger(name, passengers=None):
    if passengers is None:
        passengers = []

    print(id(passengers))
    passengers.append(name)
    return passengers

Now separate calls normally create separate list objects:

140312841284672
140312840921216
140312842034048
QUIZ ALERT
id() lets you inspect object identity. Repeated identical IDs in the bad version demonstrate that the same mutable object is being reused.
Safe vs suspicious

What Defaults Should Make You Nervous?

✅ Usually safe immutable defaults

def example(
    count=0,
    rate=0.5,
    name="Rose",
    active=True,
    value=None
):
    ...

🚨 Suspicious mutable defaults

def example(
    items=[],
    details={},
    flags=set()
):
    ...
Safe quiz answer: use None, then create the list/dict/set inside the function.

🧠 Quick check

Which default is the problem: count=0, name="Rose", notes=[], or active=True?

notes=[]

A list is mutable and can be reused across calls.

Module summary

🚨 Mutable defaults remember more than you think.

Lists, dictionaries, sets, method defaults, and nested mutable objects can all accidentally preserve state between calls because the default object is created once at function definition time. The standard safe pattern is simple: default to None, then create a fresh mutable object inside the function.
