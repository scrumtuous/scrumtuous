Warm-up

Read Code You Didn't Write

Most professional code you touch was written by somebody else. Before changing unfamiliar code, practice predicting what it does.

def flag_classes(passengers, min_count=3):
    counts = {}

    for p in passengers:
        counts[p["pclass"]] = (
            counts.get(p["pclass"], 0) + 1
        )

    return {
        pclass: n
        for pclass, n in counts.items()
        if n >= min_count
    }
QUIZ ALERT
This function uses three concepts at once: dictionary accumulation with .get(), a for loop, and a dictionary comprehension that filters results.

Quiz Connection

Dictionary Accumulation, Again

One of the most useful plain-Python data patterns is counting or summing by key.

counts = {}

for passenger in passengers:
    key = passenger["pclass"]

    counts[key] = (
        counts.get(key, 0) + 1
    )
QUIZ ALERT
dict.get(key, default) avoids a KeyError on the first sighting of a key. This is the manual logic pandas groupby() will replace later.

GenAI

Use It as a Learning Aid, Not a Crutch

GenAI is useful when it helps you understand, review, and improve code you can already explain.

✅ Good Uses

  • “Explain what this traceback means.”
  • “What edge cases might this function miss?”
  • “Is there a cleaner way to write this nested if?”
  • “Explain this comprehension in plain English.”

🚫 Not Good

  • “Write the entire assignment for me.”
  • Submitting code you cannot explain.
  • Accepting a rewrite without checking behavior.
  • Assuming shorter code is automatically better.
QUIZ ALERT
“More modern” or “shorter” does not automatically mean better. Compare correctness first, then readability, maintainability, and whether the change is materially better.

Step 1

Read the Passenger File Safely

import csv

def read_passengers(path):
    with open(path) as f:
        reader = csv.DictReader(f)
        return list(reader)
QUIZ ALERT
with open(...) closes the file even if an error occurs. Also remember that csv.DictReader returns field values as strings.

Step 2

Handle Malformed Rows Without Crashing

Real data is messy. One bad row should not silently corrupt your totals or crash the entire program.

for passenger in passengers:
    try:
        age = float(passenger["age"])
        fare = float(passenger["fare"])

    except (TypeError, ValueError) as e:
        print(f"Bad data: {e}")
        continue

    else:
        print("Valid row")

    finally:
        print("processed")
QUIZ ALERT
except (TypeError, ValueError) is appropriate when the handling is the same. Use else for success-only logic and finally for logic that always runs.

🚨 Your challenge

Add a custom InvalidPassengerError for impossible negative ages, and catch it separately from TypeError/ValueError.

class InvalidPassengerError(Exception):

for passenger in passengers:

Step 3

Apply Independent Business Rules

def get_flags(passenger):
    flags = []

    if float(passenger["fare"]) > 50:
        flags.append("HIGH_FARE")

    if float(passenger["age"]) < 18:
        flags.append("CHILD")

    return flags
Why separate if statements? Because the rules are independent. A child could also have a high fare.
QUIZ ALERT
Use separate if statements when multiple conditions may all be true. Use if/elif/else when branches are mutually exclusive.

Step 4

Write the Report

def write_report(results, path):
    with open(path, "w") as f:
        for result in results:
            f.write(
                f"{result['name']}: "
                f"{', '.join(result['flags'])}\n"
            )
QUIZ ALERT
with is just as important for writing as for reading. It closes the file and helps ensure buffered output is flushed properly.

📝 Your challenge
