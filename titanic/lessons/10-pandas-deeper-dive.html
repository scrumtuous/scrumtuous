Operation 1

groupby() with Multiple Aggregations

You already know how to do one aggregation. .agg([...]) lets you calculate several statistics on the same grouped column in a single call.

df.groupby("Pclass")["Fare"].agg(
    ["count", "sum", "mean"]
)

.agg(["sum", "count", "mean"]) calculates multiple summaries in one clear pipeline. This is a direct quiz concept.

Operation 2

Different Columns, Different Aggregations

A dictionary passed to .agg() lets you summarize different columns in different ways.

df.groupby("Pclass").agg({
    "Fare": ["sum", "mean"],
    "Age": "mean",
    "Survived": "mean"
})
Useful pattern: one grouping, several business questions answered at once.

Operation 3

pivot_table(): Turn a Summary Sideways

A pivot table summarizes like groupby(), but reshapes the output so one category becomes rows and another becomes columns.

pd.pivot_table(
    df,
    values="Fare",
    index="Pclass",
    columns="Sex",
    aggfunc="mean",
    fill_value=0
)
Pclassfemalemale
1......
2......
3......
QUIZ ALERT
pivot_table() is ideal for dense two-dimensional summaries. The quiz specifically expects the pattern values=..., index=..., columns=..., aggfunc=..., fill_value=0.

Quiz Connection

The fill_value=0 Gotcha

If a row/column combination has no matching records, pandas normally shows NaN.

Without fill_value

             male  female
Pclass
1            80.0    110.0
2            25.0     28.0
3            12.0      NaN

With fill_value=0

             male  female
Pclass
1            80.0    110.0
2            25.0     28.0
3            12.0      0.0
QUIZ ALERT
fill_value=0 makes missing combinations explicit as zero where that interpretation is appropriate. Otherwise the pivot contains NaN, which can be confusing and may complicate later arithmetic.

🌷 Your challenge

Why might a pivot table show NaN for one row/column combination?

Because there were no source rows matching that
combination of categories.

For a summary where "no matching rows" should mean
zero, fill_value=0 makes that explicit.
Operation 4

merge(): Bring in Another Table

A merge combines two DataFrames using a shared key, just like a SQL join.

class_info = pd.DataFrame([
    {"Pclass": 1, "ClassName": "First Class"},
    {"Pclass": 2, "ClassName": "Second Class"},
    {"Pclass": 3, "ClassName": "Third Class"}
])

merged = df.merge(
    class_info,
    on="Pclass",
    how="left"
)
Titanic passengers+ Class reference table➡️ One richer DataFrame
QUIZ ALERT
A left join is correct when the requirement is “keep every original passenger/trade row and attach reference data when available.” A right join changes the preserved row set to favor the reference table.

🔗 Your challenge

You have one row per passenger in df and a small port reference table keyed by Embarked. Which merge keeps every passenger even if the port lookup is missing?

merged = df.merge(
    ports,
    on="Embarked",
    how="left"
)
Quiz Connection

Why the Wrong Join Changes the Question

✅ Left join

Preserves every passenger row and attaches matching reference data.

🚫 Right join

Preserves every row in the reference table, including entries with no passengers. That may not match the passenger-level requirement.

QUIZ ALERT
The problem is not “right joins are bad.” The problem is choosing a join that preserves the wrong side for the business question.

🧠 Your challenge

If the business question changed to “show every known embarkation port, even ports with zero passengers,” which side should be preserved?

The reference-table side should be preserved.

Depending on table order, that could mean a right join
or swapping the tables and using a left join.
Operation 5

Time Series Basics: Parse the Date

Your synthetic ticket_purchase_date now becomes especially useful. pandas must treat it as a real datetime before time-aware operations make sense.

df = pd.read_csv(
    "titanic.csv",
    parse_dates=["ticket_purchase_date"]
)

by_date = df.set_index(
    "ticket_purchase_date"
)
QUIZ ALERT
Before resampling, the date column should be converted to datetime and used as the index. A column merely containing the word “date” does not make it a valid time series.

📅 Your challenge

If the date column is already loaded as text, convert it with pd.to_datetime() and then set it as the index.

    df["ticket_purchase_date"]
)

    "ticket_purchase_date"
)
Operation 6

resample(): groupby for Time

Once the DataFrame has a datetime index, resample() groups records into time buckets.

weekly_fares = (
    by_date["Fare"]
      .resample("W")
      .sum()
)

print(weekly_fares)
Individual ticket purchases➡️ Weekly buckets➡️ Weekly total fare
QUIZ ALERT
resample() is conceptually “groupby for time.” Common frequency codes include D for day, W for week, and M for month.

🕰️ Your challenge

import pandas as pd

df = pd.read_csv(
    "titanic.csv",
    parse_dates=["ticket_purchase_date"]
)

# 1. Multiple aggregations
class_summary = (
    df.groupby("Pclass")["Fare"]
      .agg(["count", "sum", "mean"])
)

# 2. Pivot table
survival_pivot = pd.pivot_table(
    df,
    values="Survived",
    index="Pclass",
    columns="Sex",
    aggfunc="mean",
    fill_value=0
)

# 3. Merge
class_info = pd.DataFrame([
    {"Pclass": 1, "ClassName": "First Class"},
    {"Pclass": 2, "ClassName": "Second Class"},
    {"Pclass": 3, "ClassName": "Third Class"}
])

merged = df.merge(
    class_info,
    on="Pclass",
    how="left"
)

# 4. Resample
by_date = df.set_index(
    "ticket_purchase_date"
)

weekly_fares = (
    by_date["Fare"]
      .resample("W")
      .sum()
)

print(class_summary)
print(survival_pivot)
print(merged.head())
print(weekly_fares)
