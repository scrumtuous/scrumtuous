Operation 1

Extract, Transform, Load

ETL simply separates three jobs that are often tangled together in one giant script.

📥
Extract Get raw data from the source without pretending it is already clean.
🧹
Transform Clean, validate, normalize, derive, and reshape.
📤
Load Write the trusted result somewhere downstream users can rely on. 
import pandas as pd

def extract():
    return pd.read_csv(
        "titanic-messy.csv"
    )

def transform(df):
    # Cleaning logic lives here
    clean = df.copy()

    clean = clean.drop_duplicates()

    clean["Embarked"] = (
        clean["Embarked"]
          .str.strip()
          .str.title()
    )

    return clean

def load(df, out_path):
    df.to_csv(
        out_path,
        index=False
    )
QUIZ ALERT
Separating ETL stages makes each one independently testable and reusable. The transform step is where your earlier data-cleaning logic belongs.

Operation 3

Validate Before Analysis Touches the Data

A loud test failure now is cheaper than a mysteriously wrong chart, model, or stakeholder decision later.

def test_no_missing_passenger_ids(
    clean_passengers
):
    assert (
        clean_passengers["PassengerId"]
        .notna()
        .all()
    )

def test_age_is_non_negative(
    clean_passengers
):
    assert (
        clean_passengers["Age"]
        .dropna()
        .ge(0)
        .all()
    )
QUIZ ALERT
Validation belongs before analysis. A schema or range problem should fail clearly at the pipeline boundary instead of quietly poisoning later results.

Operation 4

Validate Categories & Uniqueness

Some rules are categorical: only known values are allowed. Others are structural: a key should never repeat.

def test_sex_is_valid(
    clean_passengers
):
    valid = {
        "Male",
        "Female"
    }

    assert (
        clean_passengers["Sex"]
        .isin(valid)
        .all()
    )

def test_passenger_ids_are_unique(
    clean_passengers
):
    assert (
        clean_passengers["PassengerId"]
        .is_unique
    )
QUIZ ALERT
.isin(valid) checks each row against an allowed set, while .is_unique checks the whole Series for duplicate values.

Quiz Connection

The Deliberately Broken Test

This test looks plausible, but it contains a subtle bug.

def test_pclass_is_valid_broken(
    clean_passengers
):
    valid = {1, 2, 3}

    assert (
        clean_passengers["Pclass"]
        .isin(valid)
    )
    # missing .all()
pytest output
ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().
QUIZ ALERT
This is a direct quiz concept. .isin(valid) returns a whole Boolean Series, one True/False per row. assert needs one Boolean answer.
.isin(valid) 
0     True
1     True
2    False
3     True

Many Boolean values.

.isin(valid).all() 
False

One Boolean answer: “Were all rows valid?”

🚨 Your challenge

Why does assert df["Pclass"].isin({1,2,3}) fail with an “ambiguous truth value” error?

Because .isin(...) returns one Boolean per row,
not a single True/False value.

assert needs one Boolean, so .all() is required
to ask whether every row passed.
Operation 5

.all() vs .any()

These two reductions ask very different questions.

.all()

“Did every passenger satisfy the rule?”

df["Pclass"].isin(
    {1, 2, 3}
).all()

.any()

“Did at least one passenger satisfy the rule?”

(
    df["Fare"] > 100
).any()
QUIZ ALERT
For “every row must be valid,” use .all(), not .any(). .any() would let a dataset pass even if only one row were valid.

🧠 Your challenge

.all()

The validation should pass only when every row

Operation 6

Five Useful Validation Tests

A small set of automatic checks catches a surprising amount of bad data.

1️⃣ Required key: no missing PassengerId.
2️⃣ Uniqueness: PassengerId is unique.
3️⃣ Allowed categories: Pclass is only 1, 2, or 3.
4️⃣ Range: Fare is never negative.
5️⃣ Canonical values: Sex contains only expected normalized values.

Operation 7

Validate Early, Fail Loudly

Messy input➡️ Transform➡️ pytest validation➡️ Load trusted output➡️ EDA / models
Core principle: a loud failure at the pipeline boundary is dramatically cheaper than a silent bad-data problem discovered after reporting or modeling.
QUIZ ALERT
Tests are not just for application code. Data pipelines should test schema, allowed categories, ranges, uniqueness, and other invariants automatically.

import pandas as pd

def extract():
    return pd.read_csv(
        "titanic-messy.csv"
    )

def transform(df):
    clean = df.copy()

    clean = clean.drop_duplicates()

    clean["Sex"] = (
        clean["Sex"]
        .str.strip()
        .str.lower()
        .map({
            "male": "Male",
            "female": "Female"
        })
    )

    return clean

def load(df, out_path):
    df.to_csv(
        out_path,
        index=False
    )
